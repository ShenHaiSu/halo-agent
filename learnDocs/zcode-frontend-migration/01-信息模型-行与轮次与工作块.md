# 01 信息模型：行、轮次与工作块（Canonical Types）

> 本篇冻结重构后的类型契约。前后端照此建文件，任何渲染分歧先回本篇对类型，不争 UI。
> 对照 `zcodeDocs/04 §1-§3`，halo 在其上加 `WorkBlock` 保序层与 `ToolGroup` 合并层。

## 1. 行（ProjectionRow）：唯一真相源

沿用后端 `ConversationRow.cs` 8 种 + 前端 `projectionStore.ts` 已有定义，只做三处收紧：

```ts
// stores/projectionRows.ts（新建，替代 projectionStore.ts 内联类型）
export type RowKind =
  | 'turnHeader' | 'userInput' | 'assistantText' | 'reasoning'
  | 'toolCall' | 'subagent' | 'artifact' | 'timelineMarker';

export type TextState = 'streaming' | 'complete' | 'interrupted' | 'failed';
export type ToolStatus = 'inputStreaming' | 'pendingApproval' | 'running'
  | 'success' | 'error' | 'cancelled';

export interface ProjectionRow {
  rowId: number;            // 后端 RowIdAllocator 单调分配，永不复用，前端永不自增
  turnId: string;           // 轮归属（后端 turnIndex 派生，如 turn-7；乐观 ghost 用 optimistic_<cmdId>）
  kind: RowKind;
  assistantResponseId?: string | null; // 同一次模型 response 分组键（CUA 分组 + 工具合并用）
  // 文本载荷
  state?: TextState | ToolStatus | string | null;
  text?: string | null;            // assistantText/reasoning/userInput
  summaryText?: string | null;     // turnHeader/marker/subagent 摘要
  // 工具载荷
  toolName?: string | null; functionName?: string | null; // 读时优先 functionName
  toolStatus?: string | null;      // 读时优先 toolStatus， fallback state
  callId?: string | null; itemId?: string | null;
  inputText?: string | null;       // 定稿必带全量（replayable 档可渲染）
  outputText?: string | null;      // 终端直播流式追加 path=output.text
  progress?: unknown;              // exec 进度结构化载荷（display 并存）
  display?: unknown;               // 富结构（diff 结构、图片集、表格）
  error?: { code: string; message: string } | null;
  // subagent/artifact
  subSessionId?: string | null; artifactId?: string | null;
  // 兼容
  sourceMsgId?: string | null; extra?: Record<string, unknown>;
  optimistic?: boolean; commandId?: string | null;
}
```

不变量（单测锁死，见 `09`）：

1. `rowId` 全局单调永不复用；`removed` 不回收；重订阅后新行 `rowId` 必大于快照最大 `rowId`。
2. 追加只能进 `state=streaming/inputStreaming/running` 的行；终态行只许 `upserted` 整行替换。
3. 同一 `assistantResponseId` 的 `assistantText/reasoning/toolCall` 属同一次模型输出，前端据此做 CUA 分组与工具合并（`03`）。
4. 唯一例外：output-token `Continue` 可复用同 turn 紧邻旧 `assistantText` 行续写（后端实现，见 `08`），前端仍只看到标准 `row.delta`，无感知。
5. `toolCall` 执行参数只认 `input` 定稿（`upserted` 全量 `inputText`），`inputText delta` 只进预览。

状态机：

```text
assistantText/reasoning: (不存在) --appended(streaming)--> streaming --delta*--> streaming --upserted--> complete|interrupted|failed
toolCall: appended(inputStreaming) --delta(inputText)*--> inputStreaming --upserted--> running --upserted--> success|error|cancelled
         pendingApproval 为 running 的特化（等审批，输入已定稿），审批后转 running
```

`cancelled/interrupted` 是终态，前端显示“已停止/已中断”，**禁止映射为 done**（现状 bug，`06` 修）。

## 2. 增量（ConversationDelta）：封闭操作集不变

沿用 `zcodeDocs/04 §3` 五操作 + `coalesce` 四规则，前后端已有实现（`ConversationDelta.cs` / `projectionStore.ts coalesceDeltas`）冻结，只补两条前端纪律：

- `row.delta` 到达时若行缺席（虚拟窗口未加载）→ `no-op`，由 `rows/range` 取回，不猜。
- `coalesce` 等价单测 `applyAll(s,coalesce(ds))===applyAll(s,ds)` 必须进 CI（前后端各一份，用同一 `ProjectionFixture.json`）。

投递档位：本机 `continuous`（文本+`inputText`+`output.text` 全流），远端/回放 `replayable`（只流文本，工具只看定稿）。定稿 `upserted` 必带完整 `inputText`，否则回放端白板（后端保证，见 `08`）。

## 3. 轮次（TurnUnit）：从三桶到有序块

现状 `TurnGroup{content, reasoning, toolMessages}` 丢序（`00 §2.1`），重构为：

```ts
export interface TurnUnit {
  key: string;            // turnId
  turnId: string;
  header?: ProjectionRow | null;   // kind=turnHeader，运行权威
  userInputs: ProjectionRow[];     // kind=userInput（通常 1 行，分支重发可能多行）
  blocks: WorkBlock[];             // 按 rowId 排序的全部工作块（核心！）
  tailMarkers: ProjectionRow[];    // kind=timelineMarker/artifact（轮尾，不进折叠）
  running: boolean;                // 只看 header.state，无 header 才用 work.some(isRunning) 兜底
  telemetry?: TurnTelemetry | null;
}

export type WorkBlock =
  | { bkind: 'text'; row: ProjectionRow }
  | { bkind: 'reasoning'; row: ProjectionRow }
  | { bkind: 'toolGroup'; group: ToolGroup }  // 见 §4
  | { bkind: 'subagent'; row: ProjectionRow }
  | { bkind: 'textPair'; rows: ProjectionRow[] }; // Continue 复用期的兼容形态（过渡，见 04）

export interface ToolGroup {
  gkey: string;                    // assistantResponseId || turnId + 起始 rowId
  assistantResponseId?: string | null;
  toolRows: ProjectionRow[];       // 按 rowId 排序，合并规则见 03
  collapsedByDefault: true;
  summary: ToolGroupSummary;       // 组头渲染用，纯派生
}
export interface ToolGroupSummary {
  total: number; running: number; success: number; error: number; cancelled: number;
  pendingApproval: number; names: string[]; hasFailure: boolean; durationMs?: number | null;
}
```

组装函数（纯函数，放 `utils/buildTurnUnits.ts`，替代 `turnGroup.buildTurnGroups`）：

```ts
export function buildTurnUnits(rows: ProjectionRow[], opts?: { runningTurnIds?: Set<string> }): TurnUnit[] {
  const sorted = [...rows].filter(r => !r.optimistic || true).sort((a,b) => a.rowId - b.rowId);
  const byTurn = groupBy(sorted, r => r.turnId);
  return [...byTurn.entries()].map(([turnId, list]) => {
    const header = list.find(r => r.kind === 'turnHeader') ?? null;
    const userInputs = list.filter(r => r.kind === 'userInput');
    const tailMarkers = list.filter(r => r.kind === 'timelineMarker' || r.kind === 'artifact');
    const work = list.filter(r => r.kind==='assistantText'||r.kind==='reasoning'||r.kind==='toolCall'||r.kind==='subagent');
    const visible = work.filter(visibleWorkFilter); // 空 reasoning、EnterPlanMode 在此过滤
    const blocks = assembleBlocks(visible);          // §4 + 03 合并
    return { key: turnId, turnId, header, userInputs, blocks, tailMarkers,
      running: header ? isRunningState(header.state) : visible.some(isRunningWork),
      telemetry: pickTelemetry(list) };
  });
}
function visibleWorkFilter(r: ProjectionRow): boolean {
  if (r.kind==='reasoning' && (r.text??'').trim()==='') return false;
  if (r.kind==='toolCall' && isEnterPlanMode(toolNameOf(r))) return false;
  if (r.kind==='assistantText' && (r.text??'')==='' && r.state!=='streaming') return false; // 空终态文本不占位
  return true;
}
```

`assembleBlocks` 核心：遍历已排序 `visible`，`toolCall` 按合并规则（`03 §2`）聚成 `ToolGroup`，其余每行一块。**顺序即 `rowId` 顺序，不做任何重排**（思考→工具→正文恒序是旧约束，新模型按实际到达序渲染）。

## 4. 工具合并键（前端与后端对齐）

```text
可合并 ⟺ 相邻（中间无 text/reasoning/subagent 行）
        AND assistantResponseId 相同（同一次模型输出；缺失时回退 turnId + 60s 时间窗）
        AND 状态兼容（inputStreaming/running/success/error/cancelled 均可同组，组头汇总区分）
上限：单组最多 20 卡，超出拆组（防单组过长）。
```

后端需保证同 batch 并行工具调用共享 `assistantResponseId`（`08`），否则前端回退时间窗会误拆/误合。

## 5. 遥测与控制态（state.updated 键）

```ts
export interface TurnTelemetry { inputTokens: number|null; cachedTokens: number|null; outputTokens: number|null; protocol?: string; ttftMs?: number|null; }
export interface ControlState { phase: 'draft'|'running'|'completedSuccess'|...; canStop: boolean; queue: unknown[]; pendingInteractions: PendingApproval[]; }
```

- 组级 `telemetry` 从行 `extra.telemetry` 取（历史兼容），活轮从 `state.updated{telemetry}` 取（新权威），`budgetStatus` 只供顶栏 Σ，不进轮内（`00 §2.1` 三口径统一）。
- 审批入口只读 `pendingInteractions`，不读行文本（`03 §5`）。

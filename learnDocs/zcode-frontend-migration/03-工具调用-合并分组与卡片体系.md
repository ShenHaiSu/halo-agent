# 03 工具调用：连续调用合并展示与卡片体系

> 现状痛点见 `00 §5`。本篇规定何时合并、组头长什么样、卡片内部三段式、renderer 注册表、流式预览与审批。

## 1. 目标形态（先看效果）

```text
Turn-7 工作区（按 rowId 保序）：
  [正文] 我先并行查两处定义，再读主文件。
  [工具组 · 3 个工具 · 2 成功 1 运行 · 点击展开]   <- 收起态只占 1 行

  [正文] 查到 X，接下来改 Y。
  [工具组 · 1 个工具 · 待审批]
     └─ edit_file src/Agent.ts           待审批 [批准] [拒绝]
```

- 收起态每组 1 行，10 连击从 10 行 header → 1 行组头，首屏高度降 ~70%。
- 组内仍每卡独立 header，可单独展开看 diff/终端；组头只做汇总与批量操作（全部展开/只看失败）。

## 2. 合并规则（assembleBlocks 内实现，纯函数可测）

```ts
export function groupToolRows(rows: ProjectionRow[]): ToolGroup[] {
  // 输入已按 rowId 排序且相邻（调用方保证中间无 text/reasoning/subagent）
  const groups: ToolGroup[] = [];
  let cur: ProjectionRow[] = [];
  const flush = () => { if (cur.length) groups.push(makeGroup(cur)); cur = []; };
  for (const r of rows) {
    if (cur.length === 0) { cur.push(r); continue; }
    const prev = cur[cur.length - 1];
    if (canMerge(prev, r) && cur.length < 20) cur.push(r);
    else { flush(); cur.push(r); }
  }
  flush(); return groups;
}
function canMerge(a: ProjectionRow, b: ProjectionRow): boolean {
  const ra = a.assistantResponseId ?? null, rb = b.assistantResponseId ?? null;
  if (ra && rb) return ra === rb;                    // 同一次模型输出必合
  if ((ra ?? rb) !== null) return false;             // 一有一无不合（防跨 response 误合）
  return sameTurn(a, b) && timeWindowOk(a, b, 60_000); // 历史缺 responseId 时回退 60s 窗
}
```

- 相邻性由 `assembleBlocks` 保证：遇到 `text/reasoning/subagent` 即断组。`tailMarkers` 永不进组。
- `EnterPlanMode` 已在 `visibleWorkFilter` 剔除，不参与合并。
- 单组上限 20，超出拆组（`gkey = turnId:startRowId` 区分）。

`ToolGroupSummary` 纯派生（`01 §1`），`names` 取前 3 个工具名，余 `+N`；`hasFailure = error>0`；组头 pill 规则：有失败显示红 pill，无失败有运行显示蓝 pulse，全成功显示绿。

## 3. 组件：ToolGroupCard.vue + ToolCallCard（改造）

```text
components/chat/
  ToolGroupCard.vue   # 新建：组头 + 组内 v-for ToolCallCard + 批量操作
  ToolCallCard.vue    # 改造：拆 HeaderMemo / BodyLazy，见 §4
  ToolCardBody/       # 新建目录：FileDiffBody.vue / TerminalBody.vue / ImageBody.vue / GenericBody.vue / FallbackBody.vue
  FallbackCard.vue    # 保留，props 不变（toolName/rawJson/rowId/callId/status）
```

`ToolGroupCard` props：`{ group: ToolGroup; defaultCollapsed?: true }`。根节点：

```html
<div :data-gkey="group.gkey" data-kind="toolGroup" :data-count="group.toolRows.length" :data-has-failure="summary.hasFailure">
  <button group-head @click="toggle">🧰 {{ total }} 个工具 · {{ success }} 成功 {{ runningText }} {{ failText }} · {{ names }} · [只看失败] [全部展开]</button>
  <div v-if="expanded"><ToolCallCard v-for="r in filteredRows" :key="r.rowId" :row="r" /></div>
  <div v-else class="group-hint">点击展开查看参数与输出</div>
</div>
```

- `expanded` 缺省 `false`；失败组首次出现自动展开到“只看失败”态（`hasFailure && !userToggled` → `filter=failed` + `expanded=true` 一次）。
- `key` 必须 `rowId`（稳定，后端分配），禁止 `callId+index`（`00 §2.1` 现状 `messageKeyOf` 混用 entityId 导致动画复用错误）。
- 组内失败置顶：`filteredRows` 排序 `error > running/pendingApproval > success/cancelled`，同状态按 `rowId`。

## 4. ToolCallCard 改造：三段式 + Header/Body 分离

沿用 `zcodeDocs/06 §3` 三段式，现状已对齐 70%，补齐：

```vue
<ToolCallCard :row="ProjectionRow">
  <ToolSummaryRow :status :title />          <!-- HeaderMemo：memo 化，只依赖 rowId+toolStatus+functionName+summary -->
  <ProgressBar v-if="in_progress" />         <!-- 仅 in_progress，pendingApproval 显示审批条而非进度条 -->
  <BytesRow v-if="isFileEdit" />             <!-- 保留现状字节计数，但数据源统一见 §6 -->
  <ToolBodyLazy v-if="expanded" />           <!-- BodyLazy：IntersectionObserver 进视口才挂载 diff/图片/终端 -->
  <ToolError v-if="error" />
  <ApprovalBar v-if="pendingApproval" />     <!-- 新增：批准/拒绝按钮，读 pendingInteractions -->
</ToolCallCard>
```

性能拆分（`05` 细则，此处定接口）：

- `HeaderMemo = memo(props: {rowId, toolName, toolStatus, summary, durationMs, exitCode})`，`inputText/outputText` 变化不触发 header 重渲染（现状 `receivedBytes` 变化整卡重渲染，修）。
- `BodyLazy` 内部再按家族拆 `FileDiffBody/TerminalBody/ImageBody/GenericBody`，`resolveRenderer`（现状 `toolCallRowToCard.resolveRenderer` 保留，搬入 `toolRenderers/registry.ts`）只决定 Body，不决定 header。
- `parseArgs JSON.parse` 移入 `useToolArgs(row)` composable，带 `Map<rowId, parsed>` 缓存 + 半截 JSON tryParsePartial（只预览）。
- `diffLines split` 移入 `FileDiffBody`，15 行截断保留，加按 hunk 折叠（`showAllDiff` 改为 `expandedHunks:Set`）。

状态映射（修现状 bug）：

```ts
export const TOOL_STATUS_MAP = {
  inputStreaming: 'pending', pendingApproval: 'pending',
  running: 'in_progress', success: 'completed', error: 'failed', cancelled: 'stopped',
} as const;
// cancelled -> stopped（已停止），禁止 -> completed；interrupted 同 cancelled。
```

## 5. 流式预览 vs 执行参数（纪律重申）

- `inputText delta` 只进预览：卡面显示“正在输入参数… + 半截 JSON（只读、可展开）”，**执行只认 `input` 定稿**（`upserted` 全量 `inputText`）。`previewFromInputText`（现状保留）返回 `{input, complete}`，`complete=false` 时 Body 显示 `partial` + “待定稿” badge，不渲染执行按钮。
- `pendingApproval`：输入已定（`inputText` 全量已到），状态等审批。卡面显示定稿参数 + `ApprovalBar`，审批入口读 `projectionStore.pendingOf(sessionId)` 按 `callId` 匹配，不读 `window.__` 暗道（`06` 删暗道）。
- 未知工具：`resolveRenderer==='FallbackCard'` → 整卡换 `FallbackCard`（显示 `toolName + rawJson` 只读），永不白屏。`rawJson = row.inputText || '{}'`，`status` 走同一映射。

## 6. 字节与耗时口径统一

- `receivedBytes` 唯一口径 = 后端 `ToolCallUpdated.receivedBytes`（UTF-8，`AgentOrchestrator L493`），前端 `estimateUtf8Bytes` 只做旧后端回退（标记 `@deprecated`，有真值时不用）。
- `fileBytes`（落盘字节）只在 `ToolExecutionCompleted.fileBytes` 到达后显示“参数 X · 落盘 Y”，之前只显示“参数已接收 X”。
- `durationMs/exitCode` 只信 `ToolExecutionCompleted` 事件/行 `extra`，行缺失时显示 `-` 不估算。

## 7. 家族 renderer 清单（registry.ts 冻结映射）

| 家族 | 工具名归一（小写/下划线） | Body |
|---|---|---|
| File | read/read_file/edit/edit_file/write/write_file/apply_patch/list_dir/grep_search/grep/glob | FileDiffBody（diff）/ GenericBody（read/list/grep 输出） |
| Command | bash/exec/exec_command/execute/shell/run/terminal | TerminalBody（`output.text` 直播 + 复制/终止） |
| Agent | agent/task/spawn_subagent/spawn/subagent | AgentBody（`subSessionId` 跳转按钮，`subId` 读行结构化字段，不正则抠文本） |
| Question | askquestion/ask_question/askuser/ask_user/question | QuestionBody（选项列表 + 待回答态） |
| Image | view_image | ImageBody（缩略图懒挂载 + 原图按钮） |
| Fallback | 余 | FallbackBody |

`normToolName`（现状保留）大小写/连字符归一；新工具名先落 Fallback，再按需加家族（未知永不白屏）。

## 8. 验收

- [ ] 连续同 response 工具合并为 1 组，组头汇总正确；跨 response / 跨正文断组。
- [ ] 流式期参数预览只读 + 定稿后可执行态翻转；`pendingApproval` 审批按钮可用。
- [ ] 失败组自动“只看失败”展开一次；取消态显示“已停止”非“已完成”。
- [ ] 未知工具走 Fallback，无白屏；`key=rowId` 稳定，切卡/重载不串卡。

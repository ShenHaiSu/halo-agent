# 05 流式渲染性能：管线、增量 Markdown 与虚拟化

> 现状每 token 全量 `md.render + highlightAuto`、每轮全量 `loadSessionMessages`、窗口内全量挂载，见 `00 §2.2/2.5`。
> 本篇把每帧预算压进 16ms，长会话 5000 行保持 60fps。

## 1. 性能预算（先定数字，再谈优化）

| 场景 | 预算 | 现状实测倾向 |
|---|---|---|
| 单 `text delta` 到像素（流式） | ≤16ms（含 store apply + markdown + DOM patch） | 全量 render 经常 >50ms（千 token 后） |
| 单 `tool inputText delta` 到卡面预览 | ≤8ms（只改预览行，不碰 header/diff） | 整卡重渲染 + `JSON.parse` + diff 重算 |
| 长会话滚动帧 | 60fps，单帧 JS ≤8ms | 全量 `buildTurnGroups` + 全量高亮掉帧 |
| 轮末对账（TurnCompleted） | ≤200ms（增量帧已提前到达，只做终态翻转） | 全量 `loadSessionMessages` + 快照重建，常 >500ms |

测量方法：`performance.mark('delta-in') → rAF('paint')` 打点，`MarkdownStream` 内 `renderMs` 写入 `window.__perf.markdown`（dev only），`projectionStore.onFrame` 记录 `applyMs/coalesceMs`。

## 2. 数据层节流：store apply 与引用共享

1. **rAF 批处理帧**：桥接层收到的 `delta帧` 不直接 `onFrame`，进 `frameQueue`，`requestAnimationFrame` 合并一帧内的多帧再 `coalesceDeltas` 一次后 `apply`。`text` 高频、`tool inputText` 高频、`state.updated` 低频三队列，`tool` 状态翻转（`upserted`）插队优先（保证“运行→成功”不延迟）。
2. **引用共享**：保留现状 `onSnapshot` 的 `shallowRowEqual` 保引用（`projectionStore L678`），扩展到 `onFrame`：`applyDelta` 对未变化行保引用（现状 `applyDelta` 已 `slice` + 单行替换，正确；禁止 `rows.map(clone)` 全量拷贝）。
3. **`revision` 不抖**：`row.delta` 不 bump `revision`（后端已保证 `ConversationDelta.cs L116`），前端 `TurnUnit` 的 `computed` 以 `rows` 引用 + `seq` 为依赖，不以 `revision` 为依赖，避免每 token 全量重组装。组装用 `memoBySeq`：`seq` 未变直接返回缓存 `TurnUnit[]`。
4. **删热路径计算**：`estTokens/liveEst` 移出 `agentStore`（每 delta 一次 `codePoint` 循环），改为组头摘要按需计算 + 缓存；`hiddenToolCallIds` 的 `new Set` 每渲染重建删除（`06` 删双写后自然无用）。

```ts
// stores/projectionFrameQueue.ts（新建）
export function enqueueFrame(f: ProjectionFrame) { queues.text.push(...pickText(f)); queues.tool.push(...pickTool(f)); scheduleRafFlush(); }
function scheduleRafFlush() { if (scheduled) return; scheduled = true; requestAnimationFrame(() => { scheduled = false; flush(); }); }
function flush() { const deltas = [...queues.tool/*优先*/, ...queues.text]; useProjectionStore().onFrameCoalesced(deltas); }
```

## 3. Markdown 增量：从 O(全文) 到 O(增量)

现状 `MarkdownStream.rendered = md.render(all)` 每 token 重做。改造三步：

**Step1（P1 必做，零风险）**：删 `highlightAuto` 热路径 + 加缓存。

```ts
// markdown/highlighter.ts（新建）
const hlCache = new Map<string, string>(); // key = lang + hash(code)
export function highlight(code: string, lang: string): string {
  try {
    if (lang && hljs.getLanguage(lang)) {
      const k = lang + ':' + hash(code);
      let hit = hlCache.get(k); if (hit) return hit;
      hit = hljs.highlight(code, { language: lang }).value; hlCache.set(k, hit); return hit;
    }
    return escapeHtml(code); // 未指定语言不猜，只转义（删 highlightAuto）
  } catch { return escapeHtml(code); }
}
```

- 流式半截代码不再误判语言闪烁；缓存命中后重复 render 接近零成本。
- `tolerantMarkdown` 保留（补未闭合围栏），加表格容错：流式期若末行以 `|` 开头但无闭合 `|`，补 `|` 后渲染（防整表消失一帧）。

**Step2（P1 必做）：rAF 节流 + 双模渲染**。

```vue
<!-- MarkdownStream.vue 改造 -->
<script setup>
const throttledText = useRafThrottle(() => props.text, 30); // 正文 30ms，思考 64ms
const rendered = computed(() => md.render(tolerantMarkdown(throttledText.value, props.status)));
watch(() => props.status, (s) => { if (s==='completed') renderedFinal.value = md.render(props.text); });
</script>
```

- 流式期 30ms 合并多 delta 为一次 render；终态 `completed` 翻转时一次全量重排（与持久同一函数，保证终态一致）。
- `v-html` 全量替换保留（`markdown-it` 无增量 DOM），但靠节流把频率从每 token 降为每 30ms 一次；千 token 流式 render 次数从 ~500 次降为 ~60 次。

**Step3（P2 可选）：Worker/分块**。超长文本（>8000 字）`md.render` 移入 `IdleCallback` 分块（先渲染首屏 2000 字，余 `requestIdleCallback` 补），或 `Worker` 预解析。P1 先不做，留接口（`MarkdownStream limit` prop，`04 §6` 超长收纳依赖）。

## 4. 工具卡增量：Header/Body 分离 + 懒挂载

- `ToolCallCard` 拆 `HeaderMemo`（`memo(rowId+toolStatus+functionName+summary)`）+ `BodyLazy`（`expanded && heavyVisible` 才挂载）。`inputText/outputText` 变化只进 `BodyLazy` 的预览行，header 零重渲染（现状整卡重渲染，修）。
- `useToolArgs(row)` 缓存 `JSON.parse`（`Map<rowId+len, parsed>`），半截 JSON `tryParsePartial` 只跑一次/30ms。
- `FileDiffBody` 的 `split('\n')` 只在 `inputText` 定稿或长度变化超 1KB 时重算，流式预览行只显示“参数接收中 X KB”，不实时 diff。
- `TerminalBody`（`exec` 输出直播）`output.text` 变化节流 50ms + 自动滚底（`stick-to-bottom`，用户上翻即停，见 §5），超 6000 字截断 + “复制完整”。

## 5. 列表虚拟化：从 turnWindow 截断到真虚拟

现状 `turnWindowSize=30` 只是截断早轮，窗口内仍全量挂载。改造：

1. **P1**：保留截断，但截断粒度从 `TurnGroup` 改为 `TurnUnit`，`hiddenTurnCount` 文案不变；窗口内 `blocks` 的重型 body（diff/图片/终端）全部 `IntersectionObserver` 懒挂载（现状 `ToolCallCard.heavyVisible rootMargin 240px` 保留，扩展到 `TextBlock` 超长 + `ReasoningBlock` 展开态）。
2. **P2**：引入真虚拟（`vue-virtual-scroller` 或自研 `VirtualTimeline.vue`）：按 `TurnUnit` 为 item，`key=turnId`，动态高度（`ResizeObserver` 回填），可视区上下各 overscan 2 轮。`data-row-id` 锚点、`useTimelineNav` 顺序、`MessageContextMenu` 坐标全部基于虚拟 item 的 `getBoundingClientRect`，接口不变。
3. **图片**：`thumbnailCache/lostImageIds`（现状 `MessageTimeline L350`）抽为 `useImageThumbs()` composable，`toolThumbCache`（`ToolCallCard L440`）合并同源，失败置 `lost` + 黄字，不重试风暴（`thumbPending` 保留）。

## 6. 滚动：stick-to-bottom + 新消息 pill

```ts
// composables/useStickToBottom.ts（新建）
export function useStickToBottom(el: Ref<HTMLElement|null>) {
  const stuck = ref(true);
  const onScroll = () => { stuck.value = el.value ? (el.value.scrollHeight - el.value.scrollTop - el.value.clientHeight) < 48 : true; };
  function scrollToBottomIfStuck() { if (stuck.value) el.value!.scrollTop = el.value!.scrollHeight; }
  return { stuck, onScroll, scrollToBottomIfStuck };
}
```

- 替换现状 `scheduleScrollTimelineToBottom` 双 rAF + 200ms timer：只在 `stuck` 时滚底；非 stuck 时右下角 pill “↓ N 条新消息（点击回到底部）”，`N` 按 `seq` 差计数。
- `jumpLockUntil`（`useTimelineNav` 跳转锁）保留，与 `stuck` 取或（跳转 1.5s 内不滚）。
- 终端直播（`TerminalBody` 内滚动）独立 `stuck`，不干扰外层时间轴。

## 7. 后端配合（投递档位，见 08）

- 本机 `continuous`：`flushWindowMs=30`，`text/inputText/output.text` 全流；文件类 `inputText` 100ms 节流保留（`StreamToRowProjector L32`），但节流的是投递不是累积（定稿 `upserted` 必带全量）。
- 远端 `replayable`：只流 `text`，工具 `delta` 不发，前端组头显示“参数待定稿”占位，定稿一次翻转。
- `coalesce` 后投递：后端 `RowProjectionStore` 出帧前先 `Coalesce`（已实现），前端再合一次（rAF 批），双保险。

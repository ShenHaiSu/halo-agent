# 09 分阶段施工计划与验收：按什么顺序改

> 本篇把 `00~08` 的全部施工项排成三期，每项有 ID、改动文件、flag、验收、可回滚点。PM 按此建任务，QA 按此验收。

## 1. 分期总览

| 期 | 目标 | 风险 | flag 缺省 |
|---|---|---|---|
| P0 数据底座（1~2 周） | `rowId` 稳定 + `TurnUnit/WorkBlock` 双跑 + 快照直供 + 收口调用 + 单向数据流骨架 | 高（动真相源），但全程双跑可回滚 | 新路径默认关，验收后开 |
| P1 体验与性能（2~3 周） | 思考独立块 + 工具组 + Markdown 增量 + Header/Body 分离 + 终端直播 + 审批/遥测键 | 中（纯前端为主 + 后端增量事件） | 逐项默认开 |
| P2 长尾（按需） | 真虚拟列表 + Worker/分块 Markdown + `Continue` 复用 + 旧代码删除 | 低 | 可选 |

- 每期结束必须达到“关 flag 回旧版像素一致”，否则不进下期。

## 5. 量化验收门（每期必测）

| 指标 | 方法 | 门限 |
|---|---|---|
| 工具 burst 首屏高度 | 10 连击 fixture 截图量高 | 下降 ≥60% |
| 千 token 流式 render 次数 | dev 打点 `window.__perf.markdown` | <100 次 |
| 流式单帧 p95 | `delta-in→paint` | <16ms |
| 5000 行滚动帧率 | perf 面板 | ≥55fps |
| 轮末对账 | network + mark | <200ms，零 `getSessionMessages`（除切卡/重订阅） |
| rowId 稳定 | 重进会话 `data-row-id` 快照 diff | 零变化 |
| 断档恢复 | 注入 `fromSeq` 跳号 | 重订阅后终态一致 |
| 关 flag 回退 | 全关截图 diff | 与基线像素一致 |

## 6. 风险与回滚

| 风险 | 缓解 | 回滚 |
|---|---|---|
| 真快照缺席/字段缺失 | `zcode-snapshot-direct` 关回本地派生；`sanitizeSnapshot` 缺字段保旧 | 关 flag |
| 新组装顺序争议 | 双跑对照测试（工具数/文本总长一致） | 关 `zcode-turn-units` |
| Markdown 终态闪变 | 双模同函数 + 截图 diff 门 | 关 `zcode-markdown-stream` 回旧 `v-html`（临时） |
| 工具状态误映射 | `TOOL_STATUS_MAP` 单测 + 取消/失败 e2e | 回旧映射单文件 revert |
| 性能回退 | 每期 perf 门，不达标不合并 | revert 当期 P1-4/P1-5 |

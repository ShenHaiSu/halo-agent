## 2. 总量与风险

- **总量**：新建约 6 文件（组装器/行/增量/投影器/投影存储/桥接），重写约 4 文件（Dispatcher/投影存储/agentStore 瘦身/MessageTimeline），改造约 8 文件。**单人全职约 4~5 周（含测试与联调）**，双人并行（前后端分开）可压到 2.5~3 周。
- **最大风险**：前后端 `apply/coalesce` 不一致（长会话漂移）→ 用同一组 fixture 双端跑等价单测。
- **次大风险**：过渡期双事件 + 行增量并存导致双影/跳动 → 用 `DeliveryProfile` 开关 + `hiddenToolCallIds` 机制灰度，先单会话试行。
- **不建议**：一次性删 `messages.jsonl` 全量链路；一次性换 `ToolCallCard` 全部分支。都留开关。

## 3. 阶段 DoD

- P0：`Stage03` 网关测试 + 兼容端 200 缺字段/403 业务码用例全绿；`LlmGatewayClient` 无回退。
- P1：`coalesce` 等价单测 + 行投影单测 + 前后端 fixture 一致；长会话不断档；取消/切换模型无旧流污染。
- P2：未知工具不白屏；半截 JSON 不可执行；复制/审批入口收口；虚拟列表长会话不卡。

# 05 业务投影与增量通道对比

> zcode04 ↔ halo `AgentOrchestrator:440,459 / HostBridgeFacade:694,842 / JsEventDispatcher / SessionStreamEventDto`

## 1. 一句话

zcode 把“流事件 → 行 → 增量帧”放在后端，前端只做 `apply`；halo 把“流事件”直接推前端 + 轮次点全量回拉，前端自己拼卡片状态。**这是全量迁移中最大的一块重写。**

## 2. 行模型：halo 缺失

- zcode 行（8 种）：`turnHeader/userInput/assistantText/reasoning/toolCall/subagent/artifact/timelineMarker`，字段纪律：`rowId` 单调永不复用、`turnId` 归属、`assistantResponseId` 同 response 分组、不变量“追加只进 `streaming` 行、新回复必新 `rowId`”（Continue 复用紧邻旧 text 除外）。
- halo 只有消息模型 `UnifiedChatMessage`（`WorkspaceModels.cs:134`），无行。`SessionStreamEventDto{SessionId,Kind,TextDelta,ToolCall{CallId,ItemId,FunctionName,ArgumentsJson},Usage,ErrorCode,ErrorMessage}`（`UnifiedLlmModels.cs:232`）是流事件载荷，不是行。
- **施工**：新建 `Services/Projection/ConversationRow.cs`（行类型 + `RowIdAllocator`）+ `ConversationDelta.cs`（见 §3）。`messages.jsonl` 继续做持久源，行只做传输投影，不替换落盘格式（避免迁移历史会话）。

## 3. 增量操作集：halo 只有一半

| zcode 封闭集 | halo 现状 | 施工 |
|---|---|---|
| `row.appended`（99% 尾部追加） | `ToolCallStarted` 建卡 + `AssistantMessagePersisted` 落盘 | 保留语义，改载荷为行 |
| `row.upserted`（整行替换，状态机迁移） | `ToolCallUpdated(args 全量回补)` 近似，但无整行语义 | 升级为整行替换 |
| `row.delta{rowId,path,append}`（path 仅 `text/inputText/output.text/summaryText`） | `TextDelta/ReasoningDelta/ArgsDelta` 字符串追加 | 收敛 path 白名单 + `appendToRow` 类型检查（错配 no-op） |
| `row.removed{fromRowId}`（删到尾，edit/retry 分支） | 无 | 新增；`coalesce` 屏障 |
| `state.updated{patch}`（键级整体替换，不深合并） | `TurnCompleted/UsageUpdated/control/queue` 散装在 `agent:turn-event` payload | 收敛为 `state.updated`（在场键整体替换） |
| `pluginUi.*`（live-only，不进快照） | 无 | 预留，后续插件用 |

`apply` 必须前后端各一份、逐字节一致（C# + TS），`upserted/removed` 找不到行时 no-op（未加载窗口），由 `rows/range` 取回。

## 4. 合并规则：halo 只有字符串合并

- zcode `coalesce` 封闭四规则 + `removed` 屏障 + `upserted` 只留最后一条 + “合并等价”单测（`applyAll(s,coalesce(ds))===applyAll(s,ds)`）。
- halo `JsEventDispatcher:10`（175 行）：`ConcurrentQueue + 16ms Timer + MaxBatch128 → DequeueBatchJson → CoalesceEnvelopes（同 session 连续 Text/Reasoning 合并 TextDelta）+ CompactCamelCase → ExecuteScriptAsync(window.__haloReceiveHostEvents(batch))`。只有文本合并，无操作合并。
- **施工**：`JsEventDispatcher` 加 `CoalesceDeltas`（操作级合并，规则照抄 zcode 四条），保留 16ms 窗；`continuous` 本机 30ms 刷、`replayable` 远端 150ms 只流文本（halo 现文件写 150ms 节流可复用为 replay 档）。

## 5. 投递档位与收口

- zcode 双档位：本机 `continuous`（工具输入/输出尾窗也流）vs 远端 `replayable`（只流文本，定稿 `upserted` 带完整 `inputText`）。
- halo：单档位 + 文件写节流。**施工**：加 `DeliveryProfile` 开关（本机默认 continuous）；定稿 `upserted` 必须带完整 `inputText`（回放端没收过 delta 也能渲染）。
- 废弃 attempt 收口：zcode 要求模型切换/取消时 `streaming→interrupted`、未定稿工具 `→cancelled`；halo 只停 CTS。**施工**：在 `CancelSessionRun/CancelAgentTree` + 模型切换分支显式产出收口增量。

## 6. 通道映射（过渡期兼容）

过渡期保留双通道名避免前端大爆炸：

```text
llm:stream-event  → 行增量帧（row.appended/delta/upserted），payload 由 SessionStreamEventDto 换为 ConversationDelta[]
agent:turn-event  → state.updated + turnHeader + lifecycle（TurnCompleted/Truncated/Cancelled/Error/Compact*/SubAgents*）
全量 getSessionMessages → 快照帧（snapshot），新增 seq/revision/subscriptionId
```

终态前端只订阅“快照 + 增量帧”，`SessionStreamEventDto` 退役。过渡期两套并存约 1 个版本，用 `DeliveryProfile` 开关切换。

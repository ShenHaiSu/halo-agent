# 02 协议分发与网关层对比

> zcode01 ↔ halo `ProviderModels / ILlmProtocolAdapter / LlmGatewayClient / HaloHttpClientFactory / SseStreamReader`

## 1. 现状并排

**zcode：** `ProviderApiType`（三值）→ `toSdkKind` → 三工厂（Responses 取 `.responses` 分支）→ fetch 洋葱（proxy→路由→安全→业务错→参数映射→协议兼容）→ 动态鉴权（先清静态认证头）。

**halo：** `LlmProtocolType{Chat,Resp}`（`Core/Models/ProviderModels.cs:10`，endpoint 注释 `chat→/v1/chat/completions, resp→/v1/responses`）→ `ILlmProtocolAdapter{Protocol,ResolveEndpointUrl,SerializeRequest,ParseStreamAsync,FormatErrorResponse}`（38 行）→ `LlmGatewayClient:55` 双适配器注册 + 按 `Model.Protocol` 路由 + 找不到回退 Chat → `Channel<UnifiedStreamEvent>` 桥 `IAsyncEnumerable`（`:69`）→ `HaloHttpClientFactory`（代理/自签）+ `:318 Bearer + 自定义头 + ResponseHeadersRead`。

## 2. 逐项差异

### 2.1 协议枚举少一员，且回退掩盖配错

- halo 只有两协议，无 `anthropic-messages`。短期可不加，但枚举与校验要预留第三值，否则将来加协议要改调用方（违反 zcode“新增协议只加分支”）。
- halo 路由找不到回退 Chat（`LlmGatewayClient:110`）；zcode 要求显式失败。回退会把配错的 Responses 网关当 Chat 打，出错信息完全误导。
- **施工**：`LlmProtocolType` 加 `Anthropic=2`（先抛 `NotSupported`），未知协议抛错不回退；`ProviderConfigService` 校验 `baseUrl` 非空 + `apiType` 合法。

### 2.2 endpoint 后缀纪律缺失

- zcode：落盘只存 `baseUrl`（如 `https://host/v1`），后缀由 SDK 追加；用户填了后缀要能容错。
- halo：`ResolveEndpointUrl` 由各适配器拼后缀，但未见“用户已填后缀则去重”逻辑，易出现 `/v1/responses/responses`。
- **施工**：两适配器 `ResolveEndpointUrl` 统一做后缀归一（已含则不追加，大小写不敏感），并在设置页保存时做一次归一提示。

### 2.3 fetch 洋葱缺两层

| zcode 层 | halo 现状 | 补法 |
|---|---|---|
| `withResponsesJsonCompat`（补 `message.id/annotations`） | 无。部分 Responses 兼容端非流式 200 缺字段会整响应被拒 | 在 `LlmGatewayClient` 非 SSE JSON 修补：只对 `!IsEventStream && output[] type==message` 做最小修补，删 `content-length/encoding`（见 08 手册代码） |
| `detectBusinessError`（不看 content-type，读 64KB 有限 body 识业务码） | `FormatErrorResponse` 仅格式化；网关 `403 + {success:false,code:3007}` 且无 JSON content-type 会被误报为空补全 | 在非 2xx 分支读有限 body（`ReadLimitedAsync`）转 `ProviderBusinessError{code,message,status,headers}`，保留 `responseHeaders` 供重试算 `retry-after` |
| `withOptionMap`（reasoning 档位/maxTokens 改写） | 有雏形：400 含 `stream_options` 去 usage 重试、400 含 `strict` 去 strict 重发（`:165,180`） | 保留并收敛为统一 `OptionMapRetryPolicy`，加“只重试一次 + 首事件后禁重试”（见 04） |

### 2.4 动态鉴权顺序

- zcode：先清静态认证头，再叠请求头，避免 SDK 优先用旧凭据；账号型 provider 每次 attempt 给刷新机会，普通 Key 不走刷新。
- halo：`HeaderVariableResolver + ApplyCustomHeaders` 直接叠加，未清理旧 `Authorization`。
- **施工**：请求期 `ApplyRequestAuth` 先删 `authorization/x-api-key` 静态头再合并；`ProviderConfigService` 区分账号型与 Key 型（后者不触发 Host 刷新）。

### 2.5 SSE 解析器

- halo `SseStreamReader.cs:13/21`（101 行）：`StreamReader(UTF8,8192,leaveOpen)+ReadLineAsync+WaitAsync(ct)`，`:` 忽略，`event:/data:` 解析，多 `data:` 用 `\n` 拼，空行刷帧，EOF 刷残余。语义与 zcode 的 chunk 切分一致，可保留。
- 差：无 `isEventStream` 判定复用、无 idle 超时读取（zcode `readNextWithIdleTimeout`）。idle 超时在 04 的 runner 补，不在 reader 补。

## 3. 保留 vs 重写

- 保留：`ILlmProtocolAdapter` 接口形状、`SseStreamReader`、`Channel` 桥、`Bearer + 自定义头`、`stream_options/strict` 降级思路。
- 新增：`ResponsesJsonCompat` 修补函数、`BusinessErrorDetector`、`EndpointNormalizer`、`RequestAuthApplicator`（4 个小函数 + 单测）。
- 不做：Anthropic 适配器实现（P2+，先占位抛错）。

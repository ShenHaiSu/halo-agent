# 04 流式归一与编排层对比

> zcode03 ↔ halo `UnifiedLlmModels / ChatCompletionsAdapter:197 / ResponsesApiAdapter:196 / LlmGatewayClient / AgentOrchestrator`

## 1. 统一事件：形状像，语义缺一块

| zcode `ModelStreamEvent` | halo `UnifiedStreamEventKind`（10 种，`UnifiedLlmModels.cs:138`） | 差 |
|---|---|---|
| `start` | `Started` | 同 |
| `text_start/delta/end` | `TextDelta`（无 start/end 独立事件，靠 `Started + 累积`） | 需补文本行 open/close 语义，否则行投影要猜 |
| `reasoning_start/delta/end` | `ReasoningDelta` | 同上 |
| `tool_input_start/delta/end` + `tool_call` | `ToolCallStarted/ToolCallArgsDelta/ToolCallCompleted` | **缺 `ToolInputEnd`**：halo `ToolDone` 混了“流结束”与“终态定稿”，组装器无法区分“缺 end 的 final” |
| `finish{finishReason,usage}` | `UsageUpdated + StreamCompleted/StreamTruncated` | halo 拆得更细，可保留；`Truncated` 保护不执行是对的 |
| `error` | `StreamError/StreamCancelled` | 同 |

**施工**：在 `UnifiedStreamEventKind` 加 `ToolCallInputEnd`（或复用 `ToolDone` 拆二元），两适配器 `ParseStreamAsync` 在 `tool_calls` 流结束 / `function_call_arguments.done` 处显式产出；`tool_call.input` 只取终态（见 §2）。

## 2. 工具组装器：halo 缺失，必须新建

- zcode：`StreamingToolCallAssembler{streaming/completedInput/done}`——`start` 去重、`delta` 定稿后丢弃、`call` 若 `streaming && !completed` 则丢弃（缺 end 的 final 不可信）、`finish` 冲刷；`normalizeToolName/Input` 把 `null vs "null"` 区分开。
- halo：`Chat:197` 用 `SortedDictionary + PartialToolCallState` 边拼边推 `ToolStarted/Args/ToolDone`；`Responses:196` 按 `output_item.added(function_call)→arguments.delta→.done` 状态机。无三集合，半截 JSON 可直达执行；前端还用 `argsDelta` 估字节（`agentStore:372`）。
- **施工**（C# 新文件 `LlmGateway/ToolCallAssembler.cs`，约 120 行 + 单测）：
  1. `Handle(event)` 按上表四分支实现；
  2. `NormalizeName`（空→占位、大小写收敛）+ `NormalizeInput`（`JsonElement` 原样，不做 `??` 覆盖）；
  3. `AgentOrchestrator` 与 `HostBridgeFacade.StartSessionRun` 改为消费组装后事件；执行参数只用 `ToolCallCompleted.ArgumentsJson` 终态。

## 3. 流式循环与重试：halo 有降级、无边界

- zcode：`runStreamText`——并发槽（`acquireSlot`）→ `buildSdkRequest` → `fullStream` → `readNextWithIdleTimeout` → 组装 → `yield`；首有效事件后 `emittedBoundary=true` 不再整请求重试；退避 sleep 前先归还槽；Anthropic thinking 签名清理重试；每次 attempt 发 `model_request_started/completed/failed/retry_scheduled/stream_stalled`。
- halo：`Channel + Task.Run(ExecuteStreamPipelineAsync)`；400 `stream_options→去 usage 重试`、400 `strict→StripStrict 重发一次`（`LlmGatewayClient:165,180`）；无并发槽（CefSharp 单机够用）、无 idle 超时、无首事件边界、无 attempt 状态事件（仅 `IterationStarted/FirstToken/...` 在编排层）。
- **施工**：
  1. 加 `emittedContentEvent` 标记：首个 `Text/Reasoning/ToolStarted` 后，降级重试一律停（只转 `StreamError`）；
  2. 加 `IdleTimeout(默认 60s)` + `stream_stalled` 事件（复用 `agent:turn-event` 通道）；
  3. 降级重试收敛为 `OptionMapRetryPolicy{MaxOnce}`，sleep 前释放 Http 租约；
  4. 状态事件复用现有 `IterationStarted/FirstToken`，新增 `RetryScheduled`（前端显示“第 N 次重试”）。

## 4. Agent 编排循环：halo 已完整，只需接行投影

halo `AgentOrchestrator:97 RunAgentTurn`（1242 行）已实现：Heal → 追加用户（含 `PendingSessionImages`）→ `ResolveProviderModel` → 轮首冻结 `turnActiveSet` → `for iteration`（`TruncateToBudget(1024,residentStable)` → `GetActiveDefinitions` → `StreamAsync` 累积 → 落盘 Assistant → 无 calls 则 `TurnCompleted`、超轮 `TurnTruncated`、truncated 则 `ToolDiscarded` 继续 → 串行 `Dispatch + Tool消息回写(含 Images)`，spawn 走 `SubAgentCoordinator.Barrier`）→ `PublishTurnEvent(agent:turn-event)` + `PublishStreamDelta(llm:stream-event)`（`:440,459,1197,1215`，文件写 150ms 节流）。

- zcode 的业务投影（`SessionEvent + stream fact → ConversationDelta`）在 halo 中对应位置就是 `PublishTurnEvent/PublishStreamDelta` 这两处。**不要重写循环，只在这两处之后加“行投影”分支**（见 05/08）。
- 必须补：废弃 attempt 收口（模型切换/取消时把 `streaming` 文本标 `interrupted`、未定稿工具标 `cancelled`），否则旧流续写污染新分支。halo `CancelSessionRun/CancelAgentTree` 只停 CTS（`HostBridgeFacade:842`），无收口。
- `usage` 口径：halo `UsageUpdated` 实测优先 + `UsageRecorder.CollectAuto` 估算兜底 + `EnqueueFlush` 轮末写 `usage.db`，与 zcode（Anthropic total 不叠加 cache）一致，保留。

## 5. 非流式归一

- zcode：`normalizeToolCalls` 取 `toolCallId ?? id ?? uuid` + `normalizeName/Input`；`toolResults` 复用同 id 归一后 input。
- halo：非流式路径少（`generateText` 仅压缩/标题用），同样要走组装器归一，避免 `invalid-tool-call` 半截输入泄漏。施工时把非流式也过一遍 `ToolCallAssembler`。

# 03 请求投影层对比

> zcode02 ↔ halo `ChatCompletionsAdapter:27 / ResponsesApiAdapter:27 / MultimodalPlanner / ToolDefinition / SystemPromptBuilder`

## 1. 总入口形状

- zcode：`buildSdkRequest{messages,tools,toolChoice,temperature,…,providerOptions,headers,maxRetries:0}`，`apiFormat` 来自 `providerOptions.apiFormat`，重试由自家 runner 做、SDK 不重试。
- halo：`UnifiedLlmRequest{RequestId,Provider,Model,HeaderContext,SystemInstructions,Messages,Tools,ImageResolver}`（`UnifiedLlmModels.cs:13`）→ `LlmGatewayClient:119 SerializeRequest + TrackRequest/BuildSnapshot(prefixHash=Hash(payload))`。无中间 IR，直调适配器。`maxRetries=0` 思想一致（只做一次降级重发）。

## 2. 六条规则逐项

### 2.1 system 合并：halo 未定义多 system 行为

- zcode：只有 `openai-compatible` 需要合并开头多个 system，原序拼接、不加空白、保留末条 `cacheControl`；Anthropic 保留多条保缓存边界。
- halo：Chat 把 `SystemInstructions(string)` 放 `messages[0]{role:system}`；Resp 放 `instructions` + 额外 `system→{role:developer}`（`ResponsesApiAdapter:48`）。`Messages` 里若再出现 `role=system`，两适配器均无合并逻辑。
- **施工**：在 `SerializeRequest` 前加 `NormalizeSystemMessages(kind)`：仅 Chat 合并开头连续 system；Resp 保持 `instructions + developer` 不动。只改 wire，不改 `messages.jsonl` 事实。

### 2.2 Responses 推理回放剥离：halo 暂无此坑

- zcode 触发条件五合一（`openai + openai-responses + 无 previousResponseId/conversation + store!==false`）才丢 `reasoning{itemId}` + 空壳 reasoning。
- halo 无 reasoning 引用回放设计（`ReasoningContent` 只是文本），无需照抄。记为 P2 预留：将来若服务端支持 `store=true` 引用，必须补。

### 2.3 空工具名占位：halo 缺失（小改必补）

- zcode：`projectToolName`——Anthropic 保留原文，OpenAI wire 占位 `empty_tool_name`；工具消息缺 `toolCallId/toolName` 直接抛 `InvalidModelRequest`。
- halo：未占位；`ToolRegistry.Dispatch` 对 `UNKNOWN_TOOL` 有处理，但请求投影侧空名会直接被 wire 拒。
- **施工**：两适配器 `SerializeTools` 入口加占位；`UnifiedChatMessage` 校验缺 id 抛错（ fail fast）。

### 2.4 空 content 占位：文案不统一

- zcode：固定 `(no content)`，只在 wire 边界加，不改会话事实与标题种子。
- halo：附件-only 时 Resp 用 `图片如下：`、Chat 有空文本直发风险（provider 可能 trim 后判缺 prompt）。
- **施工**：统一 `EMPTY_USER_FALLBACK="(no content)"`；两适配器 `toUserContent` 为空时用它；标题种子仍用原文（不污染）。

### 2.5 媒体：halo 更细，保留 + 补两处

halo 已有（保留）：`MultimodalPlanner.PlanTurn` 仅 user/tool 可带图；`ImageResolver`（读盘 + 本轮缓存）+ `ImageDataRegistry` 补 `data:mime;base64,`；非视觉抛 `NonVisionModelException`（`Orchestrator:346` 预剥 + 通知，Adapter 兜底抛）；超 `ResolveMaxImages(0→4)` 保最新 N；`detail=NormalizeDetail(非法→high)`；Chat 展为 `image_url`、Resp 展为 `input_image`；tool 附图追加跟随 user 消息；预算每存活图 +1000 token。

要补：
1. 不支持媒体时转文字说明（`[Image omitted: <mime>]`），不静默丢——halo 缺字节时“省略”是对的，但要给文本占位以保语义。
2. video 用 file part 承载的显式映射（zcode 要求；halo 现只有 image，若接 video 必须补）。

### 2.6 工具声明：已对齐 90%

- zcode：`strict` 任一条件不满足就发原 schema；`eagerInputStreaming=false` 默认关；`requiresMfjsToolSchema` 时 `#/properties` 提升到 `#/$defs/zcode_ref_N`。
- halo：`ToolSchemaBuilder.Build{type:object,properties,required,additionalProperties:false}`（188 行）+ `ToolDefinition.ToChatToolJson{function.strict} / ToResponsesToolJson{顶层strict}`（133 行）+ `ResolveStrict(Prefer默认true/Off不发)` + `OrderBy(name)` 保前缀稳定 + 400 strict 降级。已对齐。
- **施工**：只补 `$defs` 提升（若网关需要）；`GetActiveDefinitions` 的 `Hidden(edit可执行不声明)/Disabled + preset/allow/deny` 交集（`ToolRegistry:99`）保留不动。

## 3. 上游输入（预算/压缩/前缀）关系

- `SystemPromptBuilder.BuildCore` 是预览与实发唯一同源（stable 全量 + `ephemeral(## 4.)` 非稳定）；`PrefixCachePredictor.BuildSnapshot` 五块 + `SplitStableSystem(## 5./## 6.)`；`TruncateToBudget` 平时零抖动、≥92% 才裁到 70%（三阶：图→中间原子组→截 memory）；`CompactionService` 独立压缩请求原子重写 jsonl。
- zcode 文档的预算/压缩是一笔带过，halo 是精细实现。**迁移时行投影必须以 halo 这套为上游输入**，不要反向简化。

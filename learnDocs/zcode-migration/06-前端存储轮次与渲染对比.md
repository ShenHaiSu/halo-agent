# 06 前端存储轮次与渲染对比

> zcode05/06 ↔ halo `stores/agentStore.ts(849) / workspaceStore.ts / turnGroup.ts / MessageTimeline.vue / ToolCallCard.vue / hostBridge.ts`

## 1. 存储：双轨 vs 投影存储

**halo 双轨：** 持久 `UnifiedChatMessage{id,role,content,reasoningContent,toolCalls,toolCallId,images}`（`hostBridge.ts:324`，存 `workspaceStore.sessionMessages`）+ 瞬态 `AgentTurnState{streamingText,streamingReasoning,toolCards[],telemetry,liveEst,subAgents}`（`agentStore:86`，按 `turns[sessionId]` 分桶）。流式 `TextDelta→+=` 追加、`UsageUpdated` 到账转实测（`:292`）；`finishTurn` 先发 `agent:turn-archived` 再清空流式容器消双影（`:629`）。

**zcode 投影存储三规则：** snapshot 整体替换 / `frame.fromSeq===snapshot.seq` 才 apply / 断档重订阅（携水位由服务端裁决 resume/快照）；`optimisticCommands` 只展示不产生事实；行引用共享 + 虚拟列表。

**差：** halo 无 seq/revision/subscriptionId，无断线语义；`ToolExecutionCompleted` 仅内存更新 + `dirtyPersisted`（`:453` 注释“跳动主因”）；全量靠轮次点 `loadSessionMessages`（`:607`）回拉对账。

**施工：** 新建 `stores/projectionStore.ts`（snapshot + `applyFrame` + `resubscribe`），`agentStore` 瘦身为视图缓存（只读投影，不再拼状态）；`workspaceStore.loadSessionMessages` 改为快照源（`rows/range` 前插去重保留）。

## 2. 轮次组装：思想一致，差 4 条纪律

- zcode `buildTurnUnits`：按 `turnId` 分组 + `turnHeader.state` 是运行权威（旧快照才用 `work.some(isRunning)` 兜底）+ 空 reasoning 裁掉 + `EnterPlanMode` 不展示 + 轮尾 marker/artifact 摘出不进折叠 + `assistantResponseId` 分组。
- halo `buildTurnGroups`（`turnGroup.ts:78`）：assistant 开新组、tool 按 `toolCallId` 命中或紧邻归 `cur`、孤立自成 `tool-<id>`、遇 user/system 则 flush。`useTimelineGroups.ts:28` 是简化遗留版（实际未用，以 `turnGroup` 为准）。
- **施工**：在 `turnGroup.ts` 加四条：① 运行态只看 `turnHeader`（需后端先下发 header 行）；② 过滤空 reasoning；③ 过滤内部切换工具；④ 轮尾摘出。过渡期无 header 时保留 `isRunningWork` 兜底。

# 01 总体对比：全链路差异总表

> 本篇是六层的总览表。每一行的详细证据与施工指向见 02~06。

## 1. 架构哲学差异

| 话题 | zcode（文档） | halo（代码） | 一句话评价 |
|---|---|---|---|
| 协议收敛点 | 只允许 `buildSdkRequest + normalizeSdkChunk` 两个函数感知协议 | 已收敛到 `ILlmProtocolAdapter.Serialize/Parse`，思想一致 | halo 骨架是对的，缺三条边界规则 |
| 工具参数信任 | 只信终态 `tool_call.input`，delta 仅预览 | 混用：`PartialToolCallState` 拼 delta，且前端用 `argsDelta` 估字节 | 必须改，错乱根因之一 |
| 状态归属 | 后端投影是权威，前端只消费行 | 前端 `agentStore` 自己维护卡片状态机 + 全量回拉对账 | 轮末跳动、双影的根因 |
| 增量语义 | 封闭操作集 + `coalesce` 等价单测 | 只有文本字符串拼接合并，无操作合并 | 长会话与远端回放必改 |
| 容错 | 未知 chunk/行/op 忽略 + 兜底卡 | 未知工具/事件多处抛错或静默丢 | 白屏隐患 |
| 存储 | snapshot 整体替换 + seq 衔接 + 重订阅 | 无 seq，全量 `getSessionMessages` 轮次点拉取 | 断线恢复语义缺失 |

## 2. 六层对照总表

### L1 协议分发

| zcode | halo | 差 |
|---|---|---|
| `ProviderApiType` 三值 + zod 锁死 | `LlmProtocolType{Chat=0,Resp=1}`（`ProviderModels.cs:10`） | 缺 `anthropic-messages`；无 zod，用 C# 校验补 |
| `toSdkKind` 三分支，Responses 取 `.responses` | `LlmGatewayClient:55` 注册双适配器，按 `Model.Protocol` 路由，缺省回退 Chat | 回退策略 zcode 禁止（必须显式），halo 回退会掩盖配错 |
| `bindModel` 冻结 factory，请求期只覆 `apiKey/headers` | 无冻结概念；`HaloHttpClientFactory + HeaderVariableResolver` 每次组 header | 需补“协议切换必须重建”纪律 |
| fetch 洋葱 6 层顺序固定 | `HaloHttpClientFactory`（代理/自签）+ `LlmGatewayClient:318` (`Bearer + 自定义头 + ResponseHeadersRead`) | 缺 Responses JSON 修补层、业务错识别层、参数映射层 |

### L2 请求投影

| zcode | halo | 差 |
|---|---|---|
| system 合并只对 `openai-compatible`，原序拼接不加空白 | Chat 把 `SystemInstructions` 放 `messages[0]`，Resp 放 `instructions` + 额外 `developer` 消息（`ResponsesApiAdapter:48`） | halo 未做“多 system 合并”，多 system 场景行为未定义；需补 |
| Responses 无状态回放剥离 stored reasoning | 无此逻辑（halo 无 reasoning 回放引用设计） | 若将来接 reasoning 引用服务端需补；现阶段记为 P2 |
| 空 toolName 投影边界占位 `empty_tool_name` | 未处理；工具消息缺 id 直接下游报错 | 需补（小） |
| 空 user content 固定 `(no content)` 只在 wire 加 | 有类似兜底但文案分散（`图片如下：`/空文本直发） | 统一文案 + 只在 wire 层加 |
| 媒体不支持转文字、不静默丢；video 用 file 承载 | `MultimodalPlanner.PlanTurn` + `ImageResolver` 已实现非视觉剥图、超限保最新 N、detail 归一 | halo 更细，保留；只补占位文案与 file/video 映射 |
| `strict` 仅首方 + `eagerInputStreaming=false` 门控 | `ToolDefinition.ResolveStrict + ToChat/ToResponses` + 400 strict 降级（`LlmGatewayClient:180`） | 已对齐；补 `requiresMfjsToolSchema → $defs` 网关兼容（若用得到） |

### L3 流式归一

| zcode | halo | 差 |
|---|---|---|
| `ModelStreamEvent` 12 变体 + `tool_input_start/delta/end + tool_call` 四段 | `UnifiedStreamEventKind` 10 种：`Started/Text/Reasoning/ToolStarted/ArgsDelta/ToolDone/Tokens/Completed/Truncated/...`（`UnifiedLlmModels.cs:138`） | 缺 `ToolInputEnd` 独立语义；`ToolDone` 混了定稿与终态 |
| 未知 chunk 返回空忽略 | Chat/Responses 解析对未知 `eventType` 基本忽略，但 `finish_reason` 分支有隐式假设 | 补显式 `default → null` + 日志 |
| `StreamingToolCallAssembler(streaming/completed/done)` | 无组装器；`SortedDictionary + PartialToolCallState` 边拼边推 | **必须新建组装器**，否则半截 JSON 污染执行 |
| 首有效事件后禁整请求重试；sleep 前归还槽 | 有 400 `stream_options/strict` 一次降级重试（`LlmGatewayClient:165,180`），无“首事件后禁重试” | 补边界标记 `emittedBoundary` |
| Anthropic thinking 签名清理重试 | 无（无 Anthropic 协议） | 暂不做，随协议扩展再做 |
| usage 注意 Anthropic total 口径 | 已处理 `cached_tokens/prompt_cache_hit_tokens`，`CacheHitRate`（`UnifiedLlmModels.cs:217`） | 对齐良好 |

### L4 业务投影与增量通道

| zcode | halo | 差 |
|---|---|---|
| 行模型 8 种 + `assistantResponseId` + `rowId` 单调 | `UnifiedChatMessage{role/content/reasoningContent/toolCalls...}`（`WorkspaceModels.cs:134`）是消息模型，无行 | **最大缺口：新建行模型** |
| 封闭增量 `appended/upserted/removed/delta/state.updated` + `apply/coalesce` | 双事件：`llm:stream-event(SessionStreamEventDto)` + `agent:turn-event{kind,payload}`，`JsEventDispatcher` 只合并相邻文本字符串 | 无操作集、无 `removed(fromRowId)`、无 `state.updated`、无屏障语义 |
| `removed` 是屏障，`coalesce` 不得跨越 + 等价单测 | 无 | 新增 + 单测锁死 |
| 双档位 `continuous/replayable`，回放端 `upserted` 带完整 `inputText` | 文件写 150ms 节流（`AgentOrchestrator:459`）是唯一档位概念 | 引入档位开关 |
| 废弃 attempt 收口 streaming 行/`cancelled` 未定稿工具 | `CancelSessionRun/CancelAgentTree` 只停 CTS，无行收口 | 补收口，否则旧分支污染新分支 |

### L5 前端存储与轮次组装

| zcode | halo | 差 |
|---|---|---|
| 存储三规则：snapshot 整体替换 / `fromSeq` 衔接 / 断档重订阅 | `workspaceStore.sessionMessages` 全量替换 + `loadSessionMessages` 轮次点拉取（`workspaceStore.ts:342`），无 seq | **新建投影存储**，保留 jsonl 作为持久源 |
| 行引用共享 + 虚拟列表 | 无共享池；`MessageTimeline` 全量渲染 | 长会话优化项 |
| `buildTurnUnits`：turnHeader 权威 + 空 reasoning/内部工具过滤 + 轮尾 marker 摘出 | `buildTurnGroups`（`turnGroup.ts:78`）：assistant 开组、tool 按 `toolCallId` 归组、孤立自成组 | 思想一致，差 4 条纪律（header 权威、空 reasoning 过滤、`EnterPlanMode` 过滤、轮尾摘出） |
| 乐观输入只展示不产生事实，超时只重订阅不重发 | `PromptComposer.sendPrompt → agentStore.sendPrompt` 有乐观 + `resetTurnState`，超时语义弱 | 补 2s 确认超时 + 只重订阅 |

### L6 前端渲染

| zcode | halo | 差 |
|---|---|---|
| 一行一 memo 叶子，分发无条件 hook + `data-row-id` | `MessageTimeline` 持久 + 流式双容器 + `toCard` 回填（`:213`），叶子未严格 memo | 结构可留，纪律需补 |
| Markdown 流式容错未闭合代码块，`completed` 后重排 | 直接渲染 markdown，无流式/完成态区分 | 补 `streaming/completed` 双模 |
| 工具先桥接（`STATUS_MAP + 预览/定稿分离 + display/progress`）再选 renderer + 兜底卡 | `ToolCallCard` 按函数名分支（edit/write diff、exec 终端、view_image、spawn_subagent），无统一桥接、无兜底 | **新建 `toolCallRowToCard` 桥接 + `resolveRenderer` + `FallbackCard`** |
| 半截 JSON 只预览不可执行；审批读 `pendingInteractions` | 预览/执行未分离；审批经 `AskUserGate/askUserStore`，链路可用但入口分散 | 分离 + 收口审批入口 |
| 前端不解析 SSE，只消费快照/增量帧 | 前端消费双事件（已归一，无 SSE），但同时拉全量对账 | 保留双事件作过渡，终态只消费行增量 |

## 3. 一句话定性

- **L1/L2：补缺口**（小改，P0 可做）。
- **L3：加组装器 + 重试边界**（中改，P0~P1）。
- **L4/L5：新建行 + 增量 + 快照存储**（重写，P1 主战场，占全量工作量 60%）。
- **L6：桥接 + 渲染纪律**（中改，P2）。

# 01 双协议定义与分发：一次分发，处处统一

> 目标：让 `openai-chat-completions` 与 `openai-responses`（以及 `anthropic-messages`）共用同一套业务接口，差异只收敛在模型装配层。

## 1. 协议类型定义

不要用字符串到处判断，先收敛到一个枚举。示意：

```ts
type ProviderApiType =
  | "anthropic-messages"
  | "openai-chat-completions"
  | "openai-responses";

interface ProviderConfig {
  providerId: string;
  apiType: ProviderApiType;
  baseUrl: string;          // 用户填的网关地址，如 https://host/v1
  apiKey?: string;
  headers?: Record<string, string>;
}
```

配套校验示意（伪代码）：

```ts
const ProviderApiTypeSchema = z.enum([
  "anthropic-messages",
  "openai-chat-completions",
  "openai-responses",
]);
```

关键纪律：

- 落盘只存 `baseUrl`，不拼 `/responses` 或 `/chat/completions` 后缀。后缀由 SDK 自己追加，否则用户填 `https://host/v1` 会被错误剥掉成 `https://host`。
- `apiType` 是唯一分发依据，业务层永远不直接读 `baseUrl` 猜协议。

## 3. 分发函数：apiType -> SDK Kind -> 工厂

这是整个兼容设计的心脏，伪代码抄走即用：

```ts
type SdkKind = "openai" | "anthropic" | "openai-compatible";

function toSdkKind(apiType: ProviderApiType): SdkKind {
  switch (apiType) {
    case "anthropic-messages": return "anthropic";
    case "openai-responses": return "openai"; // 注意：Responses 走 openai 工厂的 .responses
    case "openai-chat-completions": return "openai-compatible";
  }
}

function createLanguageModel(kind: SdkKind, ctx: {
  baseUrl: string;
  apiKey?: string;
  headers?: Record<string, string>;
  fetchImpl: typeof fetch;
  supportsStructuredOutput: boolean;
  providerName: string;
}): LanguageModel {
  switch (kind) {
    case "openai": {
      // Responses 协议
      const provider = createOpenAI({
        baseURL: ctx.baseUrl,
        apiKey: ctx.apiKey,
        headers: ctx.headers,
        fetch: withResponsesJsonCompat(ctx.fetchImpl),
      });
      return provider.responses("model-id"); // 关键：取 .responses 分支
    }
    case "anthropic": {
      const provider = createAnthropic({
        baseURL: ensureEndsWithV1(ctx.baseUrl),
        apiKey: ctx.apiKey,
        headers: withBearerFallback(ctx.apiKey, ctx.headers),
        fetch: withAnthropicCompat(ctx.fetchImpl),
      });
      return provider("model-id");
    }
    case "openai-compatible": {
      // Chat Completions 协议
      const provider = createOpenAICompatible({
        name: ctx.providerName,
        baseURL: ctx.baseUrl,
        apiKey: ctx.apiKey,
        headers: ctx.headers,
        includeUsage: true, // 兼容端 usage 默认不回，必须显式要
        supportsStructuredOutputs: ctx.supportsStructuredOutput,
        fetch: ctx.fetchImpl,
      });
      return provider("model-id");
    }
  }
}
```

要点：

- `openai-responses` 与 `openai-chat-completions` 虽然都姓 OpenAI，但工厂完全不同，前者必须取 `.responses` 分支。
- `supportsStructuredOutputs` 必须用绑定模型的真实能力，不能按供应商查表，否则已声明支持的 Schema 会被静默降为普通 JSON object。
- `bindModel` 时冻结 `baseUrl/headers/apiKey/apiType/factory`，后续 Registry 热更新不得让已创建的 Model 静默切换协议。请求期只允许覆盖 `apiKey + headers`（动态鉴权），不允许换 Endpoint。

## 4. fetch 洋葱：顺序即语义

伪代码展示洋葱组装顺序，外层先执行：

```ts
function buildFetchChain(opts: {
  providerId: string;
  kind: SdkKind;
  baseFetch: typeof fetch;
}): typeof fetch {
  let f = opts.baseFetch;
  f = withProxy(f);                 // 读 HTTP_PROXY / 自签证书
  f = withEndpointRouting(f);       // 多 endpoint / 账号路由
  f = withRequestSecurity(f);       // 凭据脱敏、请求体检
  f = withBusinessErrorDetect(f);   // 业务码转异常（见下）
  f = withOptionMap(f);             // reasoning档位/maxTokens 映射改写 body
  if (opts.kind === "openai") f = withResponsesJsonCompat(f);
  if (opts.kind === "anthropic") f = withAnthropicCompat(f);
  return f;
}
```

### Responses JSON 兼容层（必抄）

部分 Responses 兼容服务端在非流式 `200` 里会省略 `message.id` 或 `annotations`，上层 SDK 会直接拒掉整个响应。兼容层做法：只对非 SSE 的 JSON 做最小修补。

```ts
async function withResponsesJsonCompatFetch(baseFetch: typeof fetch): Promise<Response> {
  return async (input, init) => {
    const res = await baseFetch(input, init);
    if (!res.ok || isEventStream(res)) return res;
    const body = await tryParseJson(res.clone());
    if (!body || !Array.isArray(body.output)) return res;
    let changed = false;
    const output = body.output.map((item: any) => {
      if (item?.type !== "message") return item;
      let m = item;
      if (m.id === undefined && typeof body.id === "string") {
        m = { ...m, id: `msg_${randomUUID()}` };
        changed = true;
      }
      if (Array.isArray(m.content)) {
        const content = m.content.map((c: any) =>
          c?.type === "output_text" && c.annotations === undefined
            ? (changed = true, { ...c, annotations: [] })
            : c
        );
        m = { ...m, content };
      }
      return m;
    });
    if (!changed) return res;
    const headers = new Headers(res.headers);
    headers.delete("content-length");
    headers.delete("content-encoding");
    return new Response(JSON.stringify({ ...body, output }), {
      status: res.status, statusText: res.statusText, headers,
    });
  };
}
```

### 业务错误识别（403/429 里的 JSON 业务码）

网关常返回 `HTTP 403 + JSON { success:false, code:3007 }` 且不带 `content-type: application/json`。只靠状态码会误报为空补全。做法：非 2xx 一律尝试读有限长度 body（64KB 上限）解析业务码，转为 `ProviderBusinessError`，并保留 `responseHeaders` 供重试计算 `retry-after`。

```ts
async function detectBusinessError(res: Response): Promise<ProviderBusinessError | undefined> {
  if (res.ok && !isJson(res)) return undefined;
  // 非 2xx 不看 content-type，直接读 body
  const text = await readLimitedText(res.clone(), 64_000);
  const body = tryJsonParse(text);
  const code = body?.providerCode ?? body?.error?.providerCode ?? body?.code;
  const failed = body?.success === false || isNonZeroCode(code);
  if (!failed) return undefined;
  return new ProviderBusinessError({ code, message: readMessage(body), status: res.status });
}
```

## 5. 动态鉴权：静态头与请求头分离

```ts
function applyRequestAuth(snapshot: ProviderSnapshot, auth?: RequestAuth): ProviderSnapshot {
  if (!auth) return snapshot;
  // 先清静态认证头，避免 SDK 优先用旧凭据
  const cleanHeaders = stripAuthHeaders(snapshot.headers);
  return {
    ...snapshot,
    apiKey: auth.apiKey ?? snapshot.apiKey,
    headers: { ...cleanHeaders, ...auth.headers },
  };
}
```

账号型 provider（OAuth / 派生模式）每次 attempt 前给一次刷新机会；普通 API Key 模型不走刷新分支，避免把静态鉴权误送 Host 刷新。

## 6. 自查清单

- [ ] 新增协议只加 `toSdkKind` 的一个分支，不改业务调用方。
- [ ] `apiType` 变更必须重建 Model，不能热替换 factory。
- [ ] `baseUrl` 落盘不含协议后缀。
- [ ] Responses 非流式 JSON 兼容层存在且只做最小修补。
- [ ] 业务错误识别不依赖 `content-type`。

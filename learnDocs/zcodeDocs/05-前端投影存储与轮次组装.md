# 05 前端投影存储与轮次组装

> 位置对应：浏览器/桌面端收到 `snapshot + delta帧` 后，如何存、如何断线恢复、如何把平铺行组成“一轮”。

## 1. 存储三规则（背下来）

```text
1. snapshot 整体替换，绝不 merge；
2. delta 帧仅在区间衔接时应用（frame.fromSeq === snapshot.seq），断档不猜、不缓存补偿；
3. 断档时携当前水位重订阅，由服务端裁决 resume 还是重发 snapshot。
```

```ts
interface ProjectionState {
  status: "connecting" | "live" | "error" | "closed";
  snapshot: Snapshot | null;
  subscriptionId: string | null;
  optimisticCommands: { commandId: string; type: string }[]; // 已上行未确认的输入
}

function onFrame(state: ProjectionState, frame: TopicFrame) {
  if (frame.payload.kind === "snapshot") {
    return { ...state, status: "live", snapshot: frame.payload.snapshot };
  }
  // deltas 帧
  if (!state.snapshot || frame.fromSeq !== state.snapshot.seq) {
    resubscribe({ fromSeq: state.snapshot?.seq ?? 0 }); // 断档：不猜
    return state;
  }
  let next = state.snapshot;
  for (const d of frame.payload.deltas) next = applyDelta(next, d);
  next = { ...next, seq: frame.toSeq };
  notifyLiveOnly(frame.payload.deltas); // pluginUi 等 live-only 旁路
  return { ...state, status: "live", snapshot: next };
}
```

- `optimisticCommands` 只用于“命令已上行、投影未确认”时展示输入气泡，不产生任何会话事实，确认后由权威投影覆盖。
- 行结构共享池：新旧快照共用未变行的引用，虚拟列表按引用判等可跳过渲染，长会话内存与渲染量才收得住。

`hasOlderRows = window[0].rowId > firstRowId` 时展示“加载更早”，`rows/range` 按 `rowId` 前插合并，去重后按升序排。

## 3. 轮次组装：平铺行变成“一轮”

后端只给按 `rowId` 排序的平铺行，前端按 `turnId` 分组：

```ts
interface TurnUnit {
  key: string;
  turnId: string;
  header?: TurnHeaderRow;
  userInputs: UserInputRow[];
  assistantWorkRows: AssistantWorkRow[]; // assistantText/reasoning/toolCall/subagent/timelineMarker
  running: boolean;
}

function buildTurnUnits(rows: ConversationRow[], sessionPhase: string): TurnUnit[] {
  const byTurn = groupBy(rows, r => r.turnId);
  return Object.entries(byTurn).map(([turnId, list]) => {
    const header = list.find(isTurnHeader);
    const userInputs = list.filter(isUserInput);
    const work = list.filter(isAssistantWork).filter(visibleWorkFilter);
    return {
      key: turnId, turnId, header, userInputs,
      assistantWorkRows: splitTailRows(work), // 轮尾 marker/artifact 摘出
      running: header ? header.state === "running" : work.some(isRunningWork),
    };
  });
}

function visibleWorkFilter(row: ConversationRow) {
  if (row.kind === "reasoning" && row.text.trim() === "") return false; // 空思考块裁掉
  if (row.kind === "toolCall" && row.toolName === "EnterPlanMode") return false; // 内部切换不展示
  return true;
}

function isRunningWork(row: ConversationRow) {
  if (row.kind === "assistantText" || row.kind === "reasoning") return row.state === "streaming";
  if (row.kind === "toolCall") return ["inputStreaming", "pendingApproval", "running"].includes(row.status);
  return false;
}
```

裁决纪律：

- `turnHeader.state` 是轮是否运行的权威，`completed` 的主轮不因同轮后台工具又变 running。
- `isTurnHeader` 缺失的旧快照才用 `work.some(isRunning)` 兜底。
- `timelineMarker(lane=turnTailBoundary)` 与 `artifact` 放轮尾，不进“已工作”折叠区，否则最终答复会被卷进折叠。
- `assistantResponseId` 相同的 text/tool/reasoning 归一组，用于 CUA 等分组展示。

## 4. 乐观输入与确认

```ts
function sendText(text: string) {
  const commandId = randomUUID();
  pushOptimistic({ commandId, type: "sendText", text });
  transport.send({ commandId, type: "sendText", text });
  // 2s 内无权威 userInput/queue 投影则只重订阅，不重发命令
  setTimeout(() => {
    if (!hasProjectionFor(commandId)) resubscribe();
  }, 2000);
}
```

只重订阅不重发，避免输入重复。

## 5. 抄写清单

- [ ] 存储只有订阅推送能写，组件只读。
- [ ] `fromSeq` 对不上立刻重订阅，不做本地补偿。
- [ ] 行引用共享 + 虚拟列表，避免长会话卡顿。
- [ ] 轮是否运行只看 `turnHeader`，不看输入文本猜。
- [ ] 乐观展示与权威事实分离，确认后以权威为准。

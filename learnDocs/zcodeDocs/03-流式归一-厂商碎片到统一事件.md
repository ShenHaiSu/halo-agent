# 03 流式归一：厂商碎片翻译成统一流事件

> 位置对应：SDK 的 `fullStream` 出来后，逐 chunk 翻译成业务统一的 `ModelStreamEvent`。从这里开始，response/chat 协议已无差别。

## 1. 统一流事件（照抄即用）

```ts
type ModelStreamEvent =
  | { type: "start" }
  | { type: "text_start"; id: string }
  | { type: "text_delta"; id?: string; text: string }
  | { type: "text_end"; id: string }
  | { type: "reasoning_start"; id: string; providerMetadata?: Record<string, unknown> }
  | { type: "reasoning_delta"; id?: string; text: string; providerMetadata?: Record<string, unknown> }
  | { type: "reasoning_end"; id: string; providerMetadata?: Record<string, unknown> }
  | { type: "tool_input_start"; id: string; toolName: string; providerExecuted?: boolean }
  | { type: "tool_input_delta"; id: string; delta: string }
  | { type: "tool_input_end"; id: string }
  | { type: "tool_call"; toolCall: { id: string; name: string; input: unknown; providerExecuted?: boolean } }
  | { type: "finish"; finishReason: string; providerMetadata?: Record<string, unknown>; usage: ModelUsage }
  | { type: "error"; error: unknown };
```

另有 `compact_stream_boundary` 系列（`provider_response_start / content_block_start/delta/stop / stop_reason`），只给压缩恢复用，不进 UI，携带 provenance 不携带正文。

`ModelUsage` 统一为：

```ts
interface ModelUsage {
  inputTokens?: number; outputTokens?: number; totalTokens?: number;
  cacheReadTokens?: number; cacheWriteTokens?: number; reasoningTokens?: number;
  serverToolUse?: { webSearchRequests?: number; webFetchRequests?: number };
}
```

注意 Anthropic 的 `inputTokens` 已是普通输入 + cache 读写的 total，统计时不要再叠加 `cacheReadTokens`，否则上下文水位会被放大。

## 2. 翻译函数：SDK chunk -> 统一事件

```ts
function toModelStreamEvent(chunk: SdkTextStreamPart): ModelStreamEvent | undefined {
  switch (chunk.type) {
    case "start": return { type: "start" };
    case "text-start": return { type: "text_start", id: chunk.id };
    case "text-delta": return { type: "text_delta", id: chunk.id, text: chunk.text };
    case "text-end": return { type: "text_end", id: chunk.id };
    case "reasoning-start": return { type: "reasoning_start", id: chunk.id, providerMetadata: asRecord(chunk.providerMetadata) };
    case "reasoning-delta": return {
      type: "reasoning_delta", id: chunk.id,
      text: chunk.delta ?? chunk.text ?? "",
      providerMetadata: asRecord(chunk.providerMetadata),
    };
    case "reasoning-end": return { type: "reasoning_end", id: chunk.id, providerMetadata: asRecord(chunk.providerMetadata) };
    case "tool-input-start": return {
      type: "tool_input_start", id: chunk.id,
      toolName: normalizeToolName(chunk.toolName, { streamChunkType: chunk.type, toolCallId: chunk.id }),
      providerExecuted: chunk.providerExecuted,
    };
    case "tool-input-delta": return { type: "tool_input_delta", id: chunk.id, delta: chunk.delta };
    case "tool-input-end": return { type: "tool_input_end", id: chunk.id };
    case "tool-call": return {
      type: "tool_call",
      toolCall: {
        id: chunk.toolCallId,
        name: chunk.toolName, // 最终归一由组装器做
        input: chunk.input,   // 只取 final input，不从 delta 猜
        providerExecuted: chunk.providerExecuted,
      },
    };
    case "finish": return {
      type: "finish",
      finishReason: chunk.finishReason,
      usage: normalizeUsage(chunk.totalUsage),
      providerMetadata: merge(chunk.providerMetadata, chunk.response, chunk.response?.body),
    };
    case "error": return { type: "error", error: chunk.error };
    default: return undefined; // 未知 chunk 忽略，不抛错
  }
}
```

要点：

- `tool_call.input` 只取终态完整值。流式 `delta` 只是展示用预览，绝不能反解析成执行参数，否则 `null` 与 `"null"` 字符串、半截 JSON 会污染执行。
- `finish.providerMetadata` 要把 `response/responseBody/rawFinishReason` 并进来，因为网关业务码常只出现在尾部 body。
- 未知 `chunk.type` 返回 `undefined` 忽略，保证新协议字段不会打断旧客户端。

## 3. 流式循环骨架（含重试与准入）

```ts
async function* runStreamText(input: {
  request: ModelTextRequest;
  resolveModel: () => ResolvedModel;
  runtime: { streamText(opts: unknown): { fullStream: AsyncIterable<SdkChunk> } };
  maxAttempts: number;
  idleTimeoutMs: number;
}): AsyncGenerator<ModelStreamEvent> {
  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    const ticket = await acquireSlot({ model: request.model }); // 进程级并发门
    try {
      const options = buildSdkRequest(request, resolved);
      const result = runtime.streamText(options);
      const iter = result.fullStream[Symbol.asyncIterator]();
      const assembler = new StreamingToolCallAssembler();
      let emittedEvent = false;
      let emittedBoundary = false; // 首个有效事件后不再重试（避免重复扣费/重复执行）
      while (true) {
        const next = await readNextWithIdleTimeout(iter, idleTimeoutMs);
        if (next.done) break;
        const event = toModelStreamEvent(next.value);
        if (!event) continue;
        if (isFirstContent(event)) emittedBoundary = true;
        for (const e of assembler.handle(event)) {
          if (isRetrySafe(e)) bufferForRetry(e); else { emittedEvent = true; yield e; }
        }
      }
      yield* assembler.flushAsFinish();
      return;
    } catch (err) {
      if (!emittedBoundary && isTransient(err)) { await sleep(backoff(attempt)); continue; }
      throw toAdapterError(err);
    } finally {
      ticket.release(); // 退避 sleep 之前先归还，不占槽
    }
  }
}
```

- `emittedRetryBoundaryEvent` 之后不重试：已经向下游吐过有效内容，重放会造成重复工具执行。
- 每次 attempt 发 `model_request_started/completed/failed/retry_scheduled/stream_stalled` 状态事件，给 UI 显示“第 N 次重试/等待槽位”。
- Anthropic thinking 签名被拒时做一次不占预算的 `reasoning-history` 清理重试（只清本次请求副本，不改会话正史）。

## 4. 工具组装器：流式去重与归一

```ts
class StreamingToolCallAssembler {
  private done = new Map<string, { name: string; input: unknown }>();
  private streaming = new Set<string>();
  private completedInput = new Set<string>();

  handle(e: ModelStreamEvent): ModelStreamEvent[] {
    switch (e.type) {
      case "tool_input_start":
        if (this.done.has(e.id)) return [];
        this.streaming.add(e.id);
        return [{ ...e, toolName: normalizeToolName(e.toolName, { toolCallId: e.id }) }];
      case "tool_input_delta":
        return this.done.has(e.id) ? [] : [e]; // 定稿后 delta 丢弃
      case "tool_input_end":
        if (this.done.has(e.id)) return [];
        this.completedInput.add(e.id);
        return [e];
      case "tool_call": {
        if (this.done.has(e.toolCall.id)) return [];
        if (this.streaming.has(e.toolCall.id) && !this.completedInput.has(e.toolCall.id)) {
          return []; // 已进流式生命周期但缺 end，final 不能替代缺失的 end
        }
        const normalized = {
          ...e.toolCall,
          name: normalizeToolName(e.toolCall.name, { toolCallId: e.toolCall.id }),
          input: normalizeToolInput(e.toolCall.input, { toolName: e.toolCall.name }),
        };
        this.done.set(normalized.id, normalized);
        this.streaming.delete(normalized.id);
        this.completedInput.delete(normalized.id);
        return [{ type: "tool_call", toolCall: normalized }];
      }
      case "finish": return [...this.flush(), e];
      default: return [e];
    }
  }
  flush() { this.streaming.clear(); this.completedInput.clear(); return []; }
}
```

`normalizeToolName` 会把空名、大小写、别名收敛；`normalizeToolInput` 把 `"null"` 字符串与 `null` 原生值区分开，不做 `??` 误覆盖。

## 5. 非流式归一（generateText）

```ts
function normalizeToolCalls(result: SdkGenerateResult) {
  return result.toolCalls.map((c, i) => ({
    id: c.toolCallId ?? c.id ?? randomUUID(),
    name: normalizeToolName(c.toolName ?? c.name, { toolCallIndex: i }),
    input: normalizeToolInput(c.input ?? c.args, { toolName: c.toolName }),
  }));
}
```

`toolResults` 复用同 id 的归一后 input，避免 invalid-tool-call 的原始半截输入泄漏。

## 6. 抄写清单

- [ ] 翻译函数对未知 chunk 返回空，不抛错。
- [ ] 工具执行参数只取终态，不解析 delta。
- [ ] 首个有效事件后不再整请求重试。
- [ ] 组装器 `streaming/completed/done` 三集合缺一不可。
- [ ] usage 统计注意 Anthropic total 口径。

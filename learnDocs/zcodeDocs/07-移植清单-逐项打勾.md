# 07 移植清单：搬到新项目时逐项打勾

> 把 01~06 的设计搬到别的项目时，按本清单逐项落实。全部打勾即达到“双协议兼容 + 文本/工具正确渲染”的及格线。

## A. 协议分发（对应 01）

- [ ] 定义 `ProviderApiType = anthropic-messages | openai-chat-completions | openai-responses`， zod 锁死。
- [ ] 写出 `toSdkKind()` 分发函数，业务层不出现协议 `if`。
- [ ] `Responses` 走 `openai(...).responses`，`Chat` 走 `openai-compatible`，两者不混用。
- [ ] `bindModel` 冻结 `baseUrl/headers/apiKey/apiType/factory`，热更新不偷换协议。
- [ ] 落盘 `baseUrl` 不含 `/responses` 或 `/chat/completions` 后缀。
- [ ] fetch 洋葱顺序固定：`proxy -> 路由 -> 安全 -> 业务错 -> 参数映射 -> 协议兼容`。
- [ ] Responses 非流式 JSON 兼容层：补 `message.id` 与 `annotations`，只做最小修补。
- [ ] 非 2xx 不看 `content-type` 直接读有限 body 识别业务码。

## B. 请求投影（对应 02）

- [ ] `system` 合并只对 `openai-compatible`，按原顺序拼接，不加空白。
- [ ] Responses 无状态回放剥离 stored reasoning（`previousResponseId/conversation/store` 三条件）。
- [ ] 空 `toolName` 只在投影边界占位（`empty_tool_name`），历史保留原文。
- [ ] 空 user content 用固定 `"(no content)"`，只在 wire 边界加。
- [ ] 媒体不支持时转文字说明，不静默丢；video 用 `file` part 承载。
- [ ] `strict` 仅首方模型放行；`eagerInputStreaming=false` 默认关。
- [ ] 缺 `toolCallId/toolName` 的工具消息直接抛错，不下游猜。

## C. 流式归一（对应 03）

- [ ] 定义统一 `ModelStreamEvent`，未知 chunk 忽略不抛错。
- [ ] 翻译函数 `toModelStreamEvent` 覆盖 `text/reasoning/tool_input/tool_call/finish/error`。
- [ ] 工具执行参数只取终态 `tool_call.input`，不解析 delta。
- [ ] 组装器三集合：`streaming/completedInput/done`，定稿后 delta 丢弃。
- [ ] 首个有效事件后不再整请求重试；退避 sleep 前先归还并发槽。
- [ ] `finish` 合并 `response/responseBody/rawFinishReason`，网关业务码可观测。
- [ ] usage 注意 Anthropic total 口径，不重复叠加 cache。

## D. 增量协议（对应 04）

- [ ] 行自包含，渲染不跨行取数。
- [ ] 操作集封闭：`appended/upserted/removed/delta/state.updated`，无字段 patch。
- [ ] `row.delta` 只追加文本，状态迁移只用 `upserted`。
- [ ] `removed(fromRowId)` 删到尾；`state.updated` 键级整体替换。
- [ ] `coalesce` 四规则 + `removed` 屏障，有“合并等价”单测。
- [ ] `row.delta` 不 bump `revision`，避免每 token 抖 CAS。
- [ ] 双档位：本机 `continuous` 流工具预览，远端 `replayable` 只流文本。

## E. 前端存储与组装（对应 05）

- [ ] `snapshot` 整体替换；`fromSeq` 对不上立刻重订阅，不本地补偿。
- [ ] 只有订阅推送能写，组件只读；乐观输入与权威事实分离。
- [ ] 行引用共享 + 虚拟列表，长会话不卡。
- [ ] 按 `turnId` 组装，运行态只看 `turnHeader`，不嗅探文本。
- [ ] 空 reasoning、内部切换工具在组装层过滤，不改协议。
- [ ] 轮尾 marker/artifact 摘出，不卷进折叠。

## F. 渲染（对应 06）

- [ ] 一行一 memo 叶子，分发组件无条件 hook。
- [ ] 文本走 Markdown 流式，`data-selectable` 在稳定 DOM 层。
- [ ] 动作行只在轮尾，复制内容是整轮合并。
- [ ] 工具先桥接（`STATUS_MAP + inputText预览 + display`）再选 renderer。
- [ ] 半截 JSON 只预览不可执行；未知工具走兜底卡。
- [ ] 审批入口读 `pendingInteractions`，不读行文本猜。
- [ ] 行根节点带 `data-row-id / data-tool-call-id / data-status`。

## G. 联调排错速查

| 现象 | 先查 |
|---|---|
| 兼容端整响应被拒 | Responses JSON 兼容层是否补 `id/annotations` |
| 续轮 5xx | 是否剥离无状态 reasoning 引用 |
| 空补全被误报 | 业务错误识别是否读了非 JSON content-type 的 body |
| 工具参数错乱 | 是否用了 delta 猜 input；`null` 是否被 `??` 覆盖 |
| 同一句被拆两段 | output-token Continue 是否复用紧邻 text 行 |
| 旧分支内容拼到新分支 | 废弃 attempt 是否收口 streaming 行与未定稿工具 |
| 长会话越用越卡 | 行引用共享与虚拟列表是否生效 |
| 旧客户端见新工具白屏 | 兜底 renderer 与未知 op 忽略是否存在 |
| 输入发两次 | 乐观确认超时后是否重发了命令（应只重订阅） |
| 轮状态乱跳 | 是否绕过 turnHeader 自行推导 running |

## H. 最小移植目录建议（新项目照此建）

```text
model/
  provider-types.ts        # ProviderApiType + 统一消息/工具/事件类型
  factory.ts               # toSdkKind + createLanguageModel + bindModel
  fetch-chain.ts           # proxy/路由/安全/业务错/参数映射/协议兼容
  request-projector.ts     # toSdkMessages + toSdkTools + system/reasoning/媒体规则
  stream-normalizer.ts     # toModelStreamEvent + usage
  tool-assembler.ts        # StreamingToolCallAssembler
  runner.ts                # runStreamText/runGenerateText + 重试/准入/idle
projection/
  rows.ts                  # 行类型
  deltas.ts                # 增量类型 + apply + coalesce + 等价单测
  store.ts                 # snapshot替换 + 帧衔接 + 重订阅
  turn-units.ts            # 按 turnId 组装 + 可见性过滤
ui/
  RowView.tsx              # 按 kind 分发
  TextRow.tsx              # Markdown 流式
  ReasoningRow.tsx         # 折叠思考
  ToolCard.tsx             # 桥接 + renderer 选择 + 三段式卡片
```

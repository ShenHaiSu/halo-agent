# 06 前端渲染：文本流式与工具卡片

> 位置对应：`TurnUnit` 拿到后，按行类型分发到独立渲染叶子。本篇是“如何正确展示信息和 toolCall、如何接收并解析 delta”的前端答案。

## 1. 行分发：一个 kind 一个 memo 叶子

```tsx
function ConversationRowView({ row, context }: { row: ConversationRow; context: RenderContext }) {
  switch (row.kind) {
    case "assistantText": return <AssistantTextRowView row={row} context={context} />;
    case "reasoning": return <ReasoningRowView row={row} />;
    case "toolCall": return <ToolCallRowView row={row} context={context} />;
    case "userInput": return <UserInputBubble row={row} />;
    case "subagent": return <SubagentRowView row={row} />;
    case "timelineMarker": return <MarkerDivider row={row} />;
    default: return null;
  }
}
```

纪律：

- 需要 hook 的行类型把 hook 留在各自组件内，分发组件里不写条件 hook，否则增删行类型必白屏。
- 每个叶子 `memo` 化，虚拟列表父级重渲染时只有引用变化的行重绘。
- 每行根节点带 `data-row-id`，框选、查找、埋点都靠它。

## 2. 文本行：Markdown 流式渲染

```tsx
const AssistantTextRowView = memo(function ({ row, context }: { row: AssistantTextRow }) {
  const streaming = row.state === "streaming";
  return (
    <div data-row-id={row.rowId} data-conversation-selectable="true">
      <MarkdownStream
        completed={row.state === "complete"}
        streaming={streaming}
        messageKey={`${row.rowId}:${row.entityId ?? ""}`}
      >
        {row.text}
      </MarkdownStream>
      {row.state === "complete" && !hideActions ? (
        <RowActions text={copyText ?? row.text} onCopy onFork onFeedback />
      ) : null}
    </div>
  );
});
```

要点：

- `row.delta(path=text)` 到达后，存储把 `row.text + append` 换引用，`MarkdownStream` 增量渲染。流式模式对未闭合代码块/表格容错，`completed` 后做一次正式排版。
- `data-conversation-selectable` 必须放在稳定 DOM 包装层，不能放在 Markdown 组件的 props 上（它不透传 `data-*`，框选逻辑会找不到区域）。
- 复制/fork/点赞只在轮尾段显示（`hideActions` 由 TurnGroup 裁决），复制内容是整轮全部 text 段合并，不是只复制最后一段。
- 流式 `reasoning` 默认收起（持续展开会挤压工具与正文空间），空 streaming 直接返回 `null`。

```tsx
const ReasoningRowView = memo(function ({ row }: { row: ReasoningRow }) {
  const streaming = row.state === "streaming";
  if (streaming && row.text.length === 0) return null;
  return (
    <Reasoning isStreaming={streaming} autoCollapseKey={streaming ? null : row.state}>
      <ReasoningTrigger streamingText={row.text} />
      <ReasoningContent>{row.text}</ReasoningContent>
    </Reasoning>
  );
});
```

## 3. 工具行：先桥接，再选 renderer

工具行不能直接渲染，必须先把协议行桥成卡片模型：

```ts
const STATUS_MAP: Record<ToolCallStatus, CardStatus> = {
  inputStreaming: "pending",
  pendingApproval: "pending",
  running: "in_progress",
  success: "completed",
  error: "failed",
  cancelled: "stopped",
};

function toolCallRowToCard(row: ToolCallRow): ToolCardNode {
  const inputPreview = row.input !== undefined
    ? { input: row.input, complete: true }
    : previewFromInputText(row.inputText); // 半截 JSON -> { input, complete:false }
  return {
    toolCall: {
      toolId: row.toolCallId,
      toolName: row.toolName,
      kind: row.toolName,
      status: STATUS_MAP[row.status],
      input: inputPreview.input,
      output: row.output?.text,
      error: row.status === "error" ? (row.error?.message ?? row.output?.text) : undefined,
      raw: {
        v4Status: row.status,
        display: row.output?.display ?? row.display,
        progress: row.progress,
        inputPreviewComplete: inputPreview.complete,
      },
    },
    childToolCalls: [], // v4 嵌套由独立行表达，不在这里嵌套
  };
}

function previewFromInputText(inputText: string) {
  if (!inputText) return { input: undefined, complete: false };
  try {
    return { input: JSON.parse(inputText), complete: true };
  } catch {
    return { input: tryParsePartialJson(inputText), complete: false }; // 半截可展示、不可执行
  }
}
```

然后按工具家族选卡片：

```tsx
function ToolCallRowView({ row, context }) {
  const node = useMemo(() => toolCallRowToCard(row), [row]);
  const Renderer = useMemo(() => resolveRenderer(node.toolCall.toolName), [node]);
  return (
    <div data-row-id={row.rowId} data-tool-call-id={row.toolCallId} data-status={row.status}>
      <Renderer node={node} context={context} />
    </div>
  );
}

function resolveRenderer(toolName: string) {
  switch (toolName) {
    case "Read": case "Edit": case "Write": return FileCard;
    case "Bash": case "Execute": return CommandCard;
    case "Agent": case "Task": return AgentCard;
    case "AskQuestion": return QuestionCard;
    default: return FallbackCard; // 未知工具永不白屏
  }
}
```

卡片内部三段式（照抄结构）：

```tsx
function ToolCard({ node }) {
  return (
    <div>
      <ToolSummaryRow status={node.toolCall.status} title={buildTitle(node)} />
      {node.toolCall.status === "in_progress" && node.raw.progress ? <ProgressBar progress={node.raw.progress} /> : null}
      <ToolBody input={node.toolCall.input} output={node.toolCall.output} display={node.raw.display} />
      {node.toolCall.error ? <ToolError text={node.toolCall.error} /> : null}
    </div>
  );
}
```

- 流式 `inputText` 只进预览，不进执行；卡片可显示“正在输入参数… + 半截 JSON”，但执行只认 `input` 定稿。
- `pendingApproval` 输入已定、展示为待执行，审批入口读 `pendingInteractions`，不读行文本猜。
- 未知工具走 `FallbackCard` 显示原文 JSON，保证新工具上线不炸旧客户端。

## 4. 前端如何“接收并解析 delta”

一句话：前端不解析 SSE，不解析厂商协议，只消费 `snapshot/delta帧`。

```ts
// 伪代码：订阅循环
const store = createProjectionStore(topic);
await store.connect(); // 拿 snapshot + subscriptionId
transport.onFrame(topic, (frame) => store.applyFrame(frame));

// store 内部
function applyFrame(frame: Frame) {
  if (frame.kind === "snapshot") replaceAll(frame.snapshot);
  else if (frame.fromSeq === snapshot.seq) applyDeltas(frame.deltas);
  else resubscribe(snapshot.seq); // 断档
}
```

- 文本 delta 到达：`assistantText.text` 变长 -> Markdown 增量。
- 工具 delta 到达：`toolCall.inputText` 变长 -> 卡片预览刷新；`upserted` 到达 -> 卡片状态翻转。
- `state.updated` 到达：`control/queue/pendingInteractions` 整体替换 -> 顶部状态条/审批弹窗刷新。

## 5. 性能与正确性纪律

- 流式文本用 `messageKey=rowId:entityId` 做流式动画 key，切换任务不复用旧动画。
- 工具卡片进入视口才挂载重型内容（diff/图片），列表用虚拟化。
- 所有“是否可见/是否运行”由行字段决定，UI 不按文本嗅探、不按时间推导。
- `early return null` 必须放在所有 hook 之后，否则增删行类型必抛 hook 数量不一致。

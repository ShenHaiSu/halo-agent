# 04 业务投影与增量协议：统一事件变成行

> 位置对应：Core 侧把 `ModelStreamEvent` 聚合成会话事实，再投影成前端可直接渲染的“行 + 增量”。

## 1. 行模型：自包含是第一纪律

每一行渲染时不需要看别的行。行类型（示意）：

```ts
type ConversationRow =
  | { kind: "turnHeader"; rowId: number; turnId: string; origin: string; state: "running"|"completedSuccess"|"completedInterrupted"|"failed"; startedAt: number }
  | { kind: "userInput"; rowId: number; turnId: string; text: string; origin: "realUser"|"synthetic"|...; attachments?: AttachmentRef[] }
  | { kind: "assistantText"; rowId: number; turnId: string; text: string; state: "streaming"|"complete"|"interrupted"|"failed"; assistantResponseId?: string }
  | { kind: "reasoning"; rowId: number; turnId: string; text: string; state: "streaming"|"complete"|"interrupted"; assistantResponseId?: string }
  | { kind: "toolCall"; rowId: number; turnId: string; toolCallId: string; toolName: string;
      status: "inputStreaming"|"pendingApproval"|"running"|"success"|"error"|"cancelled";
      inputText: string; input?: unknown; output?: { text: string; display?: unknown };
      progress?: unknown; error?: { code: string; message: string } }
  | { kind: "subagent"; rowId: number; turnId: string; summaryText: string; status: string }
  | { kind: "artifact"; rowId: number; turnId: string; displayName: string; artifactType: string }
  | { kind: "timelineMarker"; rowId: number; turnId: string; marker: { type: string; status: string }; lane: string };
```

- `rowId`：会话内单调递增，永不复用。`turnId` 是轮次归属，`entityId` 是持久实体身份。
- `assistantResponseId`：同一模型 response 的正文/工具/思考共享此 ID，前端据此分组（如 CUA 组）。
- 不变量：追加只能进 `state=streaming` 的行；普通新回复必然新 `rowId`。唯一例外是 output-token Continue，可重新打开同 turn 紧邻的旧 text 行（前端仍只看到标准增量）。

## 2. 投影分水岭：流事件到增量

```ts
function projectStreamFact(event: SessionEvent, fact: { stream: ModelStreamEvent }): ConversationDelta[] {
  const p = fact.stream;
  switch (p.type) {
    case "text_start": return openTextRow(event, fact);
    case "text_delta": {
      const open = streamingTextRowId === null ? openTextRow(event, fact) : [];
      return [...open, { op: "row.delta", rowId: streamingTextRowId, path: "text", append: p.text }];
    }
    case "text_end": return closeTextRow("complete");
    case "reasoning_start": return openReasoningRow(event, fact);
    case "reasoning_delta": {
      const open = streamingReasoningRowId === null ? openReasoningRow(event, fact) : [];
      return [...open, { op: "row.delta", rowId: streamingReasoningRowId, path: "text", append: p.text }];
    }
    case "reasoning_end": return closeReasoningRow();
    case "tool_input_start": return openToolRow(event, p);   // row.appended{status:inputStreaming}
    case "tool_input_delta": return appendToolInput(event, p); // row.delta{path:inputText}
    case "tool_input_end": return flushToolInput(p.id);        // 刷尾
    case "tool_call": return finalizeToolInput(event, p);      // row.upserted{input:定稿}
    default: return [];
  }
}

function openTextRow(event, fact) {
  closeTextRow("complete"); // 不变量：同时只允许一行 streaming 文本
  const row = { kind: "assistantText", rowId: nextRowId(), turnId: turnIdOf(event),
    text: "", state: "streaming", assistantResponseId: fact.stream.assistantResponseId };
  streamingTextRowId = row.rowId;
  return [{ op: "row.appended", row }];
}
```

工具侧补充：

- `tool_input_delta` 对文件类工具节流（如 100ms 一刷），半截 JSON 存旁表，`tool_call` 定稿时一次性替换。
- `ToolCallScheduled/Started/Progress/Result/Error` 分别对应行的创建、运行、进度、终态收口。终态用 `row.upserted` 整行替换，不做字段 patch。
- 模型切换/废弃 attempt 时，先把 `streaming` 文本标 `interrupted`，把未定稿工具标 `cancelled`，避免旧流续写污染新分支。

## 3. 增量协议：封闭操作集

```ts
type ConversationDelta =
  | { op: "row.appended"; row: ConversationRow }            // 99% 是尾部追加
  | { op: "row.upserted"; row: ConversationRow }             // 整行替换（状态机迁移）
  | { op: "row.removed"; fromRowId: number }                // 删除该行及之后（edit/retry 分支）
  | { op: "row.delta"; rowId: number; path: StreamablePath; append: string } // 文本追加
  | { op: "state.updated"; patch: StatePatch }              // 键级整体替换，绝不深合并
  | { op: "pluginUi.resourceUpdated" | "resourceListChanged" | ... }; // live-only，不改快照

type StreamablePath = "text" | "inputText" | "output.text" | "summaryText";
```

`apply` 语义（纯函数，前后端各一份，行为逐字节一致）：

```ts
function applyDelta(snapshot: Snapshot, delta: ConversationDelta): Snapshot {
  switch (delta.op) {
    case "row.appended":
      return { ...snapshot, rows: [...snapshot.rows, delta.row] };
    case "row.upserted": {
      const i = snapshot.rows.findIndex(r => r.rowId === delta.row.rowId);
      if (i === -1) return snapshot; // 未加载行 = no-op，由 rows/range 取回
      const rows = [...snapshot.rows]; rows[i] = delta.row; return { ...snapshot, rows };
    }
    case "row.removed":
      return { ...snapshot, rows: snapshot.rows.filter(r => r.rowId < delta.fromRowId) };
    case "row.delta": {
      const i = snapshot.rows.findIndex(r => r.rowId === delta.rowId);
      if (i === -1) return snapshot;
      const rows = [...snapshot.rows];
      rows[i] = appendToRow(rows[i], delta.path, delta.append);
      return { ...snapshot, rows };
    }
    case "state.updated":
      return { ...snapshot, ...delta.patch }; // 在场键整体替换
  }
}

function appendToRow(row: ConversationRow, path: StreamablePath, append: string) {
  if (path === "text" && (row.kind === "assistantText" || row.kind === "reasoning"))
    return { ...row, text: row.text + append };
  if (path === "inputText" && row.kind === "toolCall")
    return { ...row, inputText: row.inputText + append };
  if (path === "output.text" && row.kind === "toolCall" && row.output)
    return { ...row, output: { ...row.output, text: row.output.text + append } };
  if (path === "summaryText" && row.kind === "subagent")
    return { ...row, summaryText: row.summaryText + append };
  return row; // 路径与行类型不匹配 -> no-op
}
```

## 4. 合并规则：coalesce 与逐条等价

flush 窗口内的合并规则（封闭集合）：

```text
1. 相邻同 (rowId, path) 的 row.delta -> append 拼接
2. 相邻 state.updated -> patch 键浅合并（键内整体替换，安全）
3. row.delta 后随同 rowId 的 row.upserted -> 丢弃前者（整行已蕴含追加）
4. row.removed 是屏障，任何规则不得跨越
5. 相邻同 rowId 的 row.upserted 只留最后一条
```

```ts
function coalesce(deltas: ConversationDelta[]): ConversationDelta[] {
  const out: ConversationDelta[] = [];
  for (const d of deltas) {
    const last = out[out.length - 1];
    if (d.op === "row.delta" && last?.op === "row.delta"
        && last.rowId === d.rowId && last.path === d.path) {
      out[out.length - 1] = { ...d, append: last.append + d.append };
      continue;
    }
    if (d.op === "state.updated" && last?.op === "state.updated") {
      out[out.length - 1] = { op: "state.updated", patch: { ...last.patch, ...d.patch } };
      continue;
    }
    out.push(d);
  }
  return out;
}
```

黄金律：`applyAll(s, coalesce(ds)) === applyAll(s, ds)`，用单测锁死。

## 5. 投递档位：continuous vs replayable

```ts
const DELIVERY_PROFILES = {
  continuous: { flushWindowMs: 30, streamPaths: { text: true, inputText: true, "output.text": true }, toolProgress: false },
  replayable: { flushWindowMs: 150, streamPaths: { text: true, inputText: false, "output.text": false }, toolProgress: true },
};
```

- 桌面本机用 `continuous`：工具输入/输出尾窗也流式，体验最好。
- 远端/回放用 `replayable`：只流文本，工具只看定稿，减少带宽与重放歧义。定稿 `upserted` 必须带完整 `inputText`，因为回放端没收到过 `delta`。

## 6. 抄写清单

- [ ] 行自包含，渲染不跨行取数。
- [ ] `row.delta` 只追加文本，状态迁移只用 `upserted`。
- [ ] `removed` 是唯一删除语义，参数是 `fromRowId`（删到尾）。
- [ ] `state.updated` 只做键级替换。
- [ ] 合并函数有“合并等价”单测。

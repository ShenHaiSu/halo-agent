# 工具架构总览

> 面向要在另一个 Agent 项目中复现本套工具体系的工程师。本文档集不依赖任何源代码文件，可独立阅读。
> 术语：模型指大语言模型；工具指模型可调用的函数；声明指发给模型的工具介绍；执行指后端真正运行工具的逻辑。

## 1. 全量工具与默认子集

系统内置 8 个工具，分为两类：

| 名称 | 一句话能力 | 默认是否发给模型 |
|---|---|---|
| read | 读文件，支持文本分页与图片附件 | 是 |
| bash | 执行 shell 命令，返回 stdout+stderr | 是 |
| edit | 对单文件做精确文本替换，可一次多处 | 是 |
| write | 新建或全量覆盖文件，自动建父目录 | 是 |
| powershell | 与 bash 同形，跑 PowerShell 语义 | 否，需手动开启 |
| grep | 按正则或字面量搜文件内容 | 否，需手动开启 |
| find | 按 glob 找文件路径 | 否，需手动开启 |
| ls | 列目录 | 否，需手动开启 |

为什么默认只给 4 个：read+bash+edit+write 已闭环读、跑、改、建。bash 本身能兼 ls、grep、find 的活，只是体验不如专用工具。powershell 只在 Windows 相关场景需要。grep、find、ls 是只读增强，按需开启可省上下文。

另有三组快捷组合：

- 编程组合：read、bash、edit、write。
- 只读组合：read、grep、find、ls。
- 全量组合：8 个全给。

## 2. 四层模型：注册、激活、声明、提示

复现时必须分清四层，不要混为一层：

1. 注册层。进程启动时把 8 个工具的定义全部创建出来，连同扩展、MCP 远端工具一起放进注册表。注册不等于可见。
2. 激活层。决定本轮哪些工具可被执行、可被声明。默认激活编程组合。用户配置、命令行参数、SDK 参数、会话内动态切换都会改激活集。去重、有序。
3. 声明层。真正发给模型的工具介绍。每轮请求前对比历史声明与当前激活集的差异，生成增量补丁。支持隐藏声明：工具仍可被执行、可被别的工具间接调用，但不出现在请求头里，也不出现在提示词的工具列表里。
4. 提示层。系统提示词里的自然语言教学。只列激活且有简介的工具，另加规则段、文档段、工作目录段、技能段等。

数据流：

```text
启动 -> 创建8定义 -> 注册表
用户配置/参数 -> 激活集 -> 可执行集
激活集 + 隐藏规则 -> 声明集 -> 模型请求头
激活集 + 简介/规则表 -> 系统提示词 -> 模型系统消息
模型 toolCall -> 参数校验 -> 前置钩子 -> 执行 -> 后置钩子 -> 工具结果消息 -> 下一轮
```

## 3. 工具可见性：五种曝光度

每个工具都有曝光度属性，控制注册后是否自动激活、是否可声明、是否可调用：

- direct：默认。注册即激活，声明给模型，可直接调用，也可被别的工具调用。
- model-only：声明给模型，但不可被别的工具通过内部通道调用。用于编排类、交互类工具。
- codemode：注册但不激活、不声明，除非显式激活。激活后仍主要供脚本引擎调用，脚本引擎会在自己的介绍里列出它们。
- deferred：与 codemode 类似，但脚本引擎也不列出，只能靠工具搜索发现。用于延迟加载的大量工具。
- hidden：注册但永远不可达，激活也无效。用于占位或禁用。

8 个内置工具全是 direct。第三方扩展常用 codemode、deferred 来做按需加载。

## 4. 工具定义的两面：给模型看 vs 给程序用

每个工具定义同时承载两面：

给模型看：名称、描述、参数结构、约束采样标记。会被精简后发给模型。描述要写清截断、翻页、错误语义，否则模型会误解。

给程序用：执行函数、参数预处理、结构化输出结构、渲染器、曝光度、命名空间、注解、默认激活标记、loadout 调整钩子、并发模式、系统提示词简介与规则。

给 UI 看：标签、调用渲染、结果渲染、外壳样式。

执行结果也分两面：

- content：给模型看的文本或图片块数组。
- details：给 UI 看的结构化细节，如截断信息、diff、耗时。
- structuredContent：给程序调用者看的机器可读结果，如退出码、是否截断。脚本引擎优先用它，不用文本。
- isError：是否算失败。失败也返回内容，不抛异常以外的通道。
- terminate：是否建议本批执行完就停，不再继续。

## 5. 参数、校验、执行、截断四道关

所有工具共享同一套管线：

1. 参数声明用结构化模型。对象、字符串、数字、布尔、数组、可选字段，每个字段带自然语言描述。描述会原样发给模型，是最重要的教学。
2. 参数预处理。先跑兼容垫片，把模型发错形状的入参修成标准形，再做类型 coercion 与校验。校验失败返回带路径的错误，不执行。
3. 执行。统一签名：调用编号、已校验参数、中止信号、增量回调、扩展上下文。支持中止、超时、流式增量。文件写操作进串行队列，shell 与搜索支持杀进程树。
4. 截断。文本输出统一按行数与字节数双限，默认 2000 行或 50KB 先到先截。读取留头部，命令留尾部，搜索按条数先限再按字节截。截断必给继续动作，如翻页偏移、调大条数、读全量文件路径。

## 6. 文档集导读

- 01 工具定义契约：复现时先看，定义接口每个字段的含义与默认值。
- 02 Agent 循环与执行调度：模型多工具调用如何串行或并行、如何拦截改写、如何提前结束。
- 03 声明、校验与约束采样：参数如何发给模型、如何校验、如何做严格模式。
- 04 读文件工具：文本分页、图片附件、无视觉模型降级。
- 05 命令执行工具：bash 与 powershell 的进程、环境、超时、中止、大输出。
- 06 精确编辑工具：多 edit 原子替换、模糊匹配、唯一性与重叠校验、换行与 BOM 保留。
- 07 全量写文件工具：建目录、串行、防竞态。
- 08 搜索与目录工具：grep、find、ls 的外部二进制依赖、条数限制、提示文案。
- 09 基础设施：路径解析、串行队列、截断算法、输出累积器。
- 10 预提示词与注册装配：系统提示词各节模板、简介与规则装配、默认工具合并规则、技能话术。

复现顺序建议：先做 01+03 的契约与校验，再做 09 的截断与路径，再做 04、07、06、05、08 的单个工具，最后做 02 的循环与 10 的提示词装配。

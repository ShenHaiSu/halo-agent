# 03 · 会话默认名称两阶段自动标题方案（5 字即时 + 首轮 LLM 精炼）

## 1. 现状（已读代码）

- 前端 `workspaceStore.appendMessage` L307-309：`if (msg.role==='user' && cur.title==='新建会话') cur.title = msg.content.trim().slice(0,24)` —— 纯内存态，未持久化回后端（无 `renameSession` 调用）。
- Mock `hostBridge.appendSessionMessage` L1165-1167：同 24 字逻辑，有 `sess.title` 内存更新。
- 后端 `WorkspaceSessionService.AppendSessionMessageAsync` L270-285：首条 user 且标题为 `新建会话/初始会话/空` 时取**首行 24 字（+…）**持久化到 `meta.json + sessions-index.json`。
- 即现状是“24 字首句、单阶段、前后端各写一遍、前端不持久化”。需求要改成“5 字即时 + 首轮 LLM 精炼一次、此后冻结”。

## 2. 需求精读（二阶段状态机）

- **T0 新建**：标题 `新建会话`（`CreateSession` 默认，不变）。
- **T1 首条 user 发出后（不等待响应）**：标题 := 首条消息第一句话的**前 5 个字**（不是 24）。目的：发出瞬间侧栏即有区分度，无等待感。
- **T2 首轮响应结束（TurnCompleted / TurnTruncated / TurnError 均算结束，成功失败都触发一次）**：取**第一轮对话全文**（首条 user + 首轮 assistant 全文，截断上限约 2000 字）+ 生成标题提示词，向**相同模型**（本轮 `providerId/modelId`）发一次**小请求**（无工具、短输出），解析**结构化响应**得简短标题，回写会话名。
- **T3 此后**：永不再自动更新（包括第二轮及以后）；用户手动重命名（`renameSession` / 行内 `handleSaveRename` / 后端 `UpdateSessionTitleAsync`）拥有最高优先级，一旦手动改过即永久冻结自动逻辑。

## 3. 设计决策

### 3.1 “第一句话的前 5 个字”定义

```ts
// 新增 utils/sessionTitle.ts
export function instantTitleFromUserText(text: string): string {
  const firstLine = (text||'').trim().split(/[\r\n]+/).map(s=>s.trim()).filter(Boolean)[0] || '';
  // 第一句话：按 。！？!?;；分割取首段
  const firstSentence = firstLine.split(/[。！？!?;；]+/).map(s=>s.trim()).filter(Boolean)[0] || firstLine;
  const compact = firstSentence.replace(/\s+/g, '');
  return [...compact].slice(0, 5).join('') || '新建会话';
}
```
- 用 `[...str]` 按码点切（emoji 安全）；不足 5 字取全部；纯空白回退 `新建会话`；**不加 `…`**（5 字即完整语义，24 字才需省略号）。
- 前后端统一用此函数语义：前端 TS 一份，后端 C# 一份（`Take(5)` 按 `StringInfo` 文本元素切，避免 surrogate 截半）。

### 3.2 LLM 精炼请求设计（核心）

- **触发点**：前端 `agentStore` 的 `TurnCompleted/TurnTruncated/TurnError` 落桶处（`handleTurnEvent` L363-401 → `finishTurn`）。原因：只有前端知道“首轮结束”且持有本轮模型 id；后端 Agent 编排未知标题语义，不宜耦合。
- **守卫**：仅当 `sessionMessages` 中 user 条数 `===1`（即首轮）且会话标题仍为“自动态”（`新建会话` 或 T1 的 5 字 dónde 记录）才触发。实现：`workspaceStore` 加 `autoTitleDone: Record<sessionId, boolean>` + `manualRenamed: Set`（`renameSession` 成功即记）；后端 `UpdateSessionTitleAsync` 被调即视为手动，后续 Append 不再覆盖（见 §3.3）。
- **请求体**：复用 `startSessionRun / LlmGatewayClient` 的 chat 通道（`temperature 0.2, maxTokens 50`，无 tools、无 reasoning），system prompt 固定：
```
你是会话标题生成器。只根据用户首轮对话生成 4-10 个汉字的简短标题，不加标点、不加引号、不解释，只输出标题本身。若无法概括则输出首条消息前5字。
对话全文如下：
---
<user>: ...
<assistant>: ...（截断2000字）
---
```
- **结构化解析**：要求模型只输出标题纯文本；前端 `parseTitleResult(text)`：取首行、去引号/标点/前后缀（`标题：xxx` → `xxx`）、截 4–12 字；非法（空/超长/含换行多句）则**保留 T1 的 5 字**（不回退、不报错、不 toast）。
- **同模型**：用本轮 `configStore.activeProvider/activeModel`（= `startAgentTurn` 所用 id），不另选小模型；失败（网络/超时/空返回）静默放弃，T1 标题保留。超时 20s 熔断，不阻塞主流程。
- **回写**：`workspaceStore.renameSession(sessionId, llmTitle)`（走现有 `updateSessionTitle` bridge，后端持久化 + 更新 `UpdatedAtUtc`），成功后记 `autoTitleDone`。Mock bridge 同步加同样行为以便 Web 调试。

### 3.3 后端配合（最小改动二选一，推荐 A）

- **A（推荐，零新接口）**：只改 `AppendSessionMessageAsync` L270-285 的自动标题条件：`candidate = 前5字`（与前端同语义），且加冻结位：`meta.json` 新增可选字段 `TitleAutoGenerated bool`（缺省 false；老数据按“标题==新建会话/初始会话 → false”兼容）。自动覆盖仅当 `!TitleAutoGenerated-by-user && !manual`；`UpdateSessionTitleAsync`（手动）一经调用即置 `TitleAutoGenerated=false + TitleLocked=true`，此后 Append 永不碰标题。DTO 加两个可选字段，前端忽略未知字段则零破坏（`normalizeBridgePayload` 透传）。
- **B（ incomes，更干净但动桥）**：新增 `generateSessionTitle(workspaceId, sessionId, firstRoundText)` 后端接口，C# 内调 `LlmGatewayClient` 同模型小请求 + 解析 + 回写。优点：离线/Mock 一致、前端更薄；缺点：需改 `HostBridgeFacade + CefSharp binding + bridge.d.ts`，scope 大。**本次不选**，列为后续优化。

### 3.4 时序图

```
用户发送首条 → workspaceStore.appendMessage → 标题:=5字(前端内存+后端Append持久化) → 侧栏即时刷新
   → agentStore.sendPrompt(startAgentTurn 同模型) → 流式…
   → TurnCompleted(首轮结束) → 组装首轮全文 → 同模型小请求(无工具/maxTokens 50)
   → parseTitleResult → renameSession(持久化) → autoTitleDone=true → 此后冻结
   → 用户手动改名 → TitleLocked=true → 任何自动逻辑永不覆盖
```

## 5. 边界与并发

- 首轮用户连发两条才回包：以“首个 assistant 落库时 user 条数==1”为首轮判据，多 user 则取首 user+首 assistant 仍生成一次，不报错。
- 切会话 during 生成：`generateTitleAfterFirstRound` 按 `sessionId` 落盘，不碰 `activeSessionId`（仿 `refreshAfterTool` 的后台桶隔离 L407-418）。
- 删除会话 during 生成：回写前查 `sessions.find(id)`，不存在即丢弃。
- 脱机/无 Key：小请求失败 → 保留 5 字，不重试、不 toast（诊断日志 `console.warn` 一条）。

## 7. 风险与回退

- 额外小请求消耗 token/耗时：`maxTokens 50 + 无工具 + 20s 超时` 上限可控；可在设置加“关闭自动标题”开关（P2，不列入必验）。
- 标题语言污染（模型输出英文/标点）：`parseTitleResult` 强清洗 + 长度钳制；极端回退 5 字，永不写空标题。
- 回退：恢复 L270-285/L307-309 的 24 字逻辑，删 `generateTitleAfterFirstRound` 调用点即可；`TitleLocked` 字段向前兼容（老数据缺省 false）。

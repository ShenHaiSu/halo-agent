# 03 声明、校验与约束采样

> 本篇讲工具如何被翻译成模型能懂的语言，以及模型发回的参数如何被校验。复现时这是模型调得准不准的关键。

## 3.1 发给模型什么：精简声明

运行时工具含很多程序字段，不能全发。发前做精简，只留四项：名称、描述、参数、约束采样标记。精简时做一次 JSON 往返，丢掉类型系统符号键与空字段，并统一键序，保证对比稳定。

为什么只留这四项：名称用于点名，描述用于选工具，参数用于组装入参，约束采样用于要求严格输出。标签、渲染器、执行函数、提示简介一律不发，模型不需要。

对比是否改定义也用精简后的序列化字符串比对，避免引入深比较依赖。改描述或改参数都算改定义，会触发先删后加的声明补丁。

## 3.2 参数结构怎么写模型才懂

- 顶层一律是对象。每个字段有类型、描述、可选标记。必填字段缺失会校验失败。
- 字符串用于路径、命令、模式、内容。路径字段注明相对或绝对均可，命令字段注明跑在当前工作目录，模式字段注明正则还是字面量。
- 数字用于偏移、条数、超时。凡有默认值的必须在描述写清默认值，如条数默认 100、目录默认 500、查找默认 1000。凡有上限的必须写清上限行为，如达上限杀进程、给调大提示。
- 布尔用于开关，默认 false 的要写清默认 false，如忽略大小写、字面量。
- 数组用于多 edit，每项是固定形状对象。数组为空要报参数无效，不执行。

字段描述是唯一的教学，不要写实现黑话，要写模型行动指南。每个限制配继续动作，如用偏移继续、用调大条数继续、用读工具看全行。

## 3.3 收到的参数三道清洗

模型发回的参数先过三道清洗，再执行：

1. 畸形修复。先跑各工具的预处理垫片。典型修补：多 edit 被发成 JSON 字符串则解析，单个 edit 对象被发成裸对象则包成单元素数组，顶层旧形状的单 edit 被展平成数组。解析失败则保持原样交校验报错。
2. 空值归一。把显式 null 的可选字段按结构语义归一，避免 null 与缺失语义打架。
3. 类型 coercion 与校验。先做宽松类型转换，再按结构校验。校验失败抛错，错误文案含工具名、字段路径、错误原因、收到的参数原文。路径用点连接，如 edits.0.oldText。

另有两种前置失败：参数 JSON 本身解析失败会带解析错误直接抛；工具名找不到直接报工具不存在。两者都不进执行函数，直接落失败结果。

## 3.4 约束采样：要求模型严格输出

部分工具带约束采样标记，常见为 JSON 模式严格偏好。发送前按传输能力解析：

- 若传输支持严格模式且参数结构能转严格，则标记严格，模型被强制按结构输出，畸形大减。
- 若结构含严格不支持的关键字且标记只是偏好，则回落非严格，不抛错。
- 若标记是必须严格但传输不支持或结构转不了，则抛错，工具不可用。

内置的读、命令、编辑、写工具都带严格偏好，搜索与目录工具不带。复现时建议读改写命令四项全带严格偏好，搜索目录可不带。

## 3.5 传输适配

- 有的传输把系统提示放请求头外，有的放消息内。系统统一维护 transcript，发送前按能力折叠：不支持中途系统消息的把后继系统消息折叠进首条。
- 工具增量有的传输可锚定在系统消息处，有的不行。支持且历史无删除无重定义的走锚定，否则发全量。保证重放一致。
- 图片块按模型能力处理。读图工具感知当前模型是否支持图片，不支持则在文本注里声明图片将被省略，避免模型等图。

## 3.6 复现清单

- 精简声明、清洗三步、校验文案、约束采样回落，四件做对，模型误调率降大半。
- 错误文案必须含下一步，不要只说错了，要说怎么改，如补唯一上下文、调大条数、换翻页偏移。
- 所有清洗与校验放执行前，执行函数只收已校验参数，可大幅简化各工具实现。

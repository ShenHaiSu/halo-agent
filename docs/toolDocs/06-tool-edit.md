# 06 精确编辑工具

> 精确编辑用于小改文件。设计目标：一次调多处、原子落盘、匹配不唯一就拒、重叠就拒、换行与 BOM 不丢。

## 6.1 参数

- path：字符串，必填。相对或绝对均可，按工作目录解析。
- edits：数组，必填，至少一项。每项含 oldText 与 newText，均为字符串。oldText 是目标替换的精确原文，必须在原文件唯一且与其他项不重叠；newText 是替换后的新文本。所有项都相对原文件匹配，不是增量应用。若两处改动在同一块或相邻行，应合并为一项，而不是发重叠项。

## 6.2 畸形兼容：预处理垫片

模型常把 edits 发错形状，执行前先修：

1. 若 edits 是 JSON 字符串，尝试解析。解析出数组则替换，解析出单个 edit 对象则包成单元素数组。解析失败保持原样交校验报错。
2. 若 edits 本身是单个 edit 对象而非数组，则包成单元素数组。
3. 若顶层带旧形状的 oldText 与 newText 字符串，则将其作为一项追加进 edits 数组，并去掉顶层两字段。
4. 非对象输入直接透传交校验报错。

修完再校验数组非空，空数组直接报参数无效，文案大意是 edits 至少含一项替换。

## 6.3 执行步骤

1. 解析绝对路径，进同文件串行队列。队列按真实路径串行，不同文件并行。文件写中不靠中止监听放锁，只在每次等待后检查中止，保证锁释放时操作已落定。
2. 检查可读可写，不满足则报错并带系统错误码。
3. 按二进制读文件，转 UTF-8 文本，剥离 BOM 暂存。BOM 模型看不见，匹配前必须剥，否则模型永远对不上首行。
4. 探测原换行风格，归一为 LF 后匹配，写回时恢复。若原文件是 CRLF 而新内容用 LF 写回，会污染整文件 diff，必须恢复。
5. 对归一后内容做多 edit 应用，见下节。
6. 恢复换行，拼回 BOM，写文件。
7. 生成展示 diff 与标准统一补丁，算首改行，返回成功文案，文案大意是成功替换多少块加路径。细节带 diff、补丁、首改行。

## 6.4 匹配算法：精确优先，模糊兜底

每项 oldText 先精确找，再模糊找，全在归一空间进行：

- 精确：在归一后内容直接找子串。命中且唯一则用该位置。
- 模糊：对内容与 oldText 做归一：宽字符归一、逐行去行尾空格、智能单双引号转直引号、各类破折号转连字符、特殊空格转普通空格。然后在归一空间找子串。命中则在归一空间替换，结果即为新内容，不再映射回原空格。这意味着模糊命中会顺带规范化命中区的空白与标点，调用者需知晓。
- 计数：统计归一后命中次数。多于 1 则报错，文案大意是找到多处，文本必须唯一，请补更多上下文。单 edit 与多 edit 用不同文案，单 edit 报文本，多 edit 报下标。
- 重叠：把所有命中按位置排序，相邻命中若区间相交则报错，文案大意是两项重叠，请合并为一项或瞄准不相交区。重叠判断基于原文件位置，不是增量位置。

## 6.5 错误与兜底

- edits 为空：参数无效，不读文件。
- 文件不可访问：报无法编辑文件加路径加系统错误码。
- 找不到：报未找到并带路径，模型据此补上下文或先读文件。
- 不唯一：报多处命中，请补上下文，不做猜测替换。
- 重叠：报重叠，请合并，不做自动合并。
- 中止：在每次等待后检查，已中止抛操作已中止，已持有队列锁直到操作落定才放，避免半写。

## 6.6 给模型的描述与规则

- 描述写清每次针对单文件、每项 oldText 必须唯一不重叠、相邻改动合并、大段无关区不要塞进 oldText。
- 规则四条：精确改用编辑；多处改一次调多项而不是多次调；各项相对原文件不重叠；oldText 尽量小但保证唯一。
- 可用工具段简介为精确文本替换含多处一次调，一句话。
- 自绘外壳展示 diff，首改行供编辑器跳转。

## 6.7 复现要点

- 先做单 edit 精确匹配加唯一校验加原子写回，即可跑通。
- 再加多 edit 非增量定位加排序加're叠检测。
- 再加 BOM、换行保留、串行队列。
- 模糊归一最后做，有它体验好很多，但要接受命中区被规范化的副作用，并在文档写清。

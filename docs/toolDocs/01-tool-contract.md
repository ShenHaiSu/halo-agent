# 01 工具定义契约：一个工具由哪些字段组成

> 本篇是复现的起点。它规定一个工具在系统中长什么样：哪些给模型看，哪些给程序用，哪些给界面用，默认值是什么。

## 1.1 一个工具的完整形状

一个工具定义包含三组信息。复现时可以按这个顺序实现：先做标识与描述，再做参数与执行，最后做展示与调度扩展。

### 标识组

- 名称：全局唯一的小写标识，如读文件、执行命令、精确编辑、全量写、内容搜索、文件查找、列目录、PowerShell 执行。模型调用时按名称点名，系统按名称做激活、隐藏、去重。名称一旦发布不要改，改名等于新工具。
- 标签：给人看的短标签，一般与名称相同。用于日志、界面标题、调试输出。
- 描述：给模型看的长描述。必须写清能力边界、截断语义、翻页或继续动作、失败语义。模型只靠这段文字加参数表理解工具，没有别的说明书。写描述时要假设模型从没见过你的系统。

### 参数组

- 参数结构：用结构化模型声明。支持对象、字符串、数字、布尔、数组、枚举、可选字段。每个字段必须带一句自然语言描述，描述会原样发给模型。字段名用小驼峰或全小写，保持全系统一致。
- 参数预处理：可选的兼容垫片函数。输入是模型发来的原始未知参数，输出必须是符合参数结构的对象。用于修补模型常犯的形状错误。没有错误时直接透传。
- 输出结构：可选的机器可读结果结构。声明后，成功时必须设置结构化结果。脚本引擎、程序化调用者优先读它，不读文本。文本是给模型看的，结构化结果是给程序看的，两者都要填。

### 执行组

- 执行函数：异步函数，签名统一为调用编号、已校验参数、中止信号、增量回调、扩展上下文，返回工具结果。抛异常等价于返回失败结果，但推荐返回失败结果以保留细节。
- 中止信号：标准的 abort 信号。所有耗时操作必须监听，文件写操作用轮询检查，子进程用杀进程树，网络与搜索用关闭流。
- 增量回调：执行中可多次调用，用于推送部分结果，如命令的实时输出。调用者用它做流式渲染。执行结束后不再调用。
- 扩展上下文：包含工作目录、当前模型、会话管理器、内部工具调用通道。工具用它解析相对路径、感知模型能力、调用别的工具。

### 调度组

- 约束采样：可选的服务端约束采样请求。常见值是 JSON 模式严格偏好。用于要求模型按参数结构严格输出。设为 false 等价于不要求。
- 并发模式：可选的单工具覆盖。sequential 表示该工具必须独占执行，不与同批别的调用并行；parallel 表示可并行。不填则服从全局模式。
- 重放策略：用于持久化会话恢复。never 表示永不重放，safe 表示无副作用可安全重放。读、搜、列目录适合 safe，写、改、命令适合 never 或由上层决定。

### 组织组

- 曝光度：见总览的五种值。默认 direct。决定注册后是否自动激活、是否声明、是否可被内部调用。
- 命名空间：工具所属分组，如某远端服务器的工具组。包含名称、别名、短摘要、长指引。脚本引擎按组列出，搜索按组过滤。
- 可达声明：声明该工具的某次调用可能触达哪些别的工具。取值为 all 或输入文本中可能命中的词。用于延迟注册：在执行前把被触达的工具先加载完。
- 注解：沿用远端协议的提示，如只读、破坏性、幂等、开放世界。来自工具作者，不保证验证通过，供权限确认、审计参考。
- 默认激活：是否在注册时自动进入激活集。direct 与 model-only 默认 true，其他曝光默认 false。设为 false 后需用户显式点名才激活。
- 负载调整钩子：在激活集变化时被调用，可改写声明描述、隐藏部分声明。用于编排工具动态列出可调用集。

### 展示组

- 提示简介：一句话，供系统提示词的可用工具段使用。没有简介的自定义工具会被提示词省略，但仍可声明可执行。
- 提示规则：多条规则，供系统提示词的规则段使用。激活才生效，隐藏声明则同步剔除。
- 外壳样式：默认或自绘。默认由通用组件包一层彩色外壳，自绘由工具自己画框。精确编辑用自绘以便显示 diff。
- 调用渲染与结果渲染：自定义界面绘制函数。参数、主题、渲染上下文进，界面组件出。无自定义则用通用渲染。

## 1.2 工具结果的形状

执行返回的结果统一为：

- 内容：文本或图片块数组，给模型看。文本块是主体，图片块用于读图场景。至少要有一块，空输出用占位文本如无输出。
- 细节：任意结构化细节，给界面看。如截断信息、diff、补丁、首改行、耗时、条数上限标记。不发给模型。
- 结构化内容：机器可读结果，给程序看。声明了输出结构就必须填。
- 是否失败：布尔。失败时内容仍是错误说明，细节与结构化内容保留供界面与程序用。不要只在文本里写失败而不置标记，否则上层无法统计。
- 是否终止：布尔。建议本批执行完就停。仅当同批所有结果都建议终止时才真正提前结束，防止单个工具误停整批。
- 用量：可选的工具自身用量，不计入主模型上下文统计。

## 1.3 前置与后置钩子

- 前置钩子：在参数校验后、执行前调用。入参含工具调用、已校验参数、中止信号。可返回阻止执行并给出原因，或建议终止。被阻止的调用会生成一条失败工具结果，不进执行函数。用于权限确认、风控拦截、测试桩。
- 后置钩子：在执行后、发工具结束事件前调用。可按字段覆盖内容、细节、失败标记、用量、终止建议。覆盖是整字段替换，不是深合并。若只给内容不给结构化内容，则结构化内容会被丢弃，因为可能已对不上。用于脱敏、压缩、重写、审计。

## 1.4 包装关系：定义与可执行体的转换

系统内部以定义为源，以可执行体为运行时。包装函数做浅拷贝转换：名称、标签、描述、参数、输出结构、约束采样、预处理、并发模式透传，执行函数包一层上下文兜底。若调用者只给了可执行体没有定义，则反向合成一个最小定义，缺提示简介与渲染器。会话内部永远以定义为注册源，保证提示元数据不丢。

## 1.5 复现清单

- 先实现标识、描述、参数、执行、结果五件套，即可跑通最小闭环。
- 再加预处理、截断、串行、中止，即可达到生产可用。
- 最后加曝光度、命名空间、可达声明、负载钩子、渲染器，即可支持扩展与远端。
- 描述与字段描述是模型唯一的说明书，值得花最多时间打磨。每个限制都要配继续动作，每种失败都要给下一步。

# 过程盒块序不得由模板分组决定（单循环保序）

- 状态：**已闭环**（2026-11-15 修复 + 两层顺序守卫落地）
- 日期：2026-11-15
- 环境：Win10 x64 / Node 22 / Vue 3.5.43 / Vitest 2.1.9
- 现象：
  历史会话展开「过程内容」盒时，**所有工具卡置顶、思维链与过程正文全部沉底**；
  而同一轮正在流式时三类内容按出现顺序正确交织。刷新页面、重开会话都复现，
  只要走摘要盒就错——流式对、稳态错。
- 复现步骤：
  1. 打开一个有工具调用的历史轮，展开「过程内容」盒 → 工具卡全部在顶部。
  2. 同一会话新起一轮（带工具 + 思考），结束前后各看一次 → 结束瞬间（摘要接管）顺序跳变。
- 根因：
  稳态期过程盒只有一个渲染者 `TimelineProcessBox.vue`，模板里用**两个平级 `v-for`**
  先渲全部工具卡、再渲其余块；配套的 `pairToolGroupsInOrder()` 返回 `{ tools, others }`
  两个数组，两数组之间已无可比的顺序键。顺序在 util 返回时丢失，
  模板用“循环先后”顶替了块序。后端落盘、桥透传、前端取回的 `ids` 序都是对的，
  纯属展示层把“已排好的序”又按类型分组拍平。
  反例警示：`seq` 不是良序键（进程重启归零、合成轮列表序与 `seq` 序不一致、压缩桩固定为 1），
  任何“前端按 `seq` 重排”的修法都会在重启续写、老会话合成轮上造出更难查的乱序。
- 解法（最小改动）：
  单遍保序投影 `buildHistoryItems()`（`features/session/utils/historyToolCards.ts`）
  把块数组映射为扁平判别联合 `HistoryItem[]`（`tool / reasoning / text / tool_result`），
  模板只留**一个** `v-for` 平铺分支；工具卡占其 `tool_call` 块位，被卡消费的
  `tool_result` 不再占位，孤儿结果按原位输出。实现内禁止 `sort(`、禁止按 `seq` 比较、
  禁止按类型分组后再拼接；配对查找只用 `Map` 做查找，不以其迭代拼装结果。
- 判据（顺序契约）：
  盒内渲染序恒等于 `getTurnBlockIds` 返回序（跨类型交织）；同 `callId` 只出 1 卡；
  点击思维链/正文不得触发 `getToolResult`；盒头计数、折叠、`missing` 页脚、
  `data-testid` 命名全部不变。
- 守护（两层，缺一不可）：
  1. 纯函数层 `historyToolCards.spec.ts`「保序」用例：交织输入、置换输入、卡位、
     重复调用/结果、孤儿原位、幂等。
  2. 组件层 `TimelineProcessBox.spec.ts`「盒内渲染序」用例：`findAll('[data-hi-kind]')`
     序列断言 + `compareDocumentPosition` 硬断言。凡改回双循环必须变红（已做一次反向验证）。
  后来者新增块类型时只许在单循环内加分支，不许另起 `v-for`；模板上方注释与本篇即防线。
- 关联提交：
  过程盒按块序渲染改动（含两层守卫用例）与本篇同批入库。
- 教训（下次如何避开）：
  1. 顺序必须由**数据结构**保证（有序数组单遍投影），不由模板结构保证；
     “两个循环先后”就是一种隐式排序，评审时见到分组渲染要先问顺序键在哪里。
  2. 凡“流式对、稳态错”，先对比两条渲染路径的循环个数，而不是先怀疑后端落盘。
  3. 守卫要断言**顺序**（`data-hi-kind` 序列 / 文档前后关系），只断言“存在”抓不住重排类 bug。

# 命名卫生门禁正则误报测试数据 id

> 日期：2026-11-24 · 场景：`build/check-naming-hygiene.mjs --cached` 在 pre-commit / CI 检查新增行过程编号。

> **后续结论（2026-11-27）**：该正则门禁误报面过大（除本文的短测试 id 外，Tailwind `h-1` 也会被拦截），现已从 pre-commit 与 CI 移除，改为仅在施工文档中约束并由代码评审人工执行。以下保留为历史问题分析，不再代表当前门禁行为。

## 现象

提交一批「历史操作加固」改动时，pre-commit 的命名卫生守卫拦截，报出如下「过程编号违规」：

```
[naming] 新增/修改行包含过程编号，请改用业务语义命名：
  src/Web.Client/src/features/agent/stores/useAgentTurn.replay.spec.ts: setActiveSessionId('s1');
  tests/HaloAgent.Tests/HistoryAnchorProjectorTests.cs: new HistoryMessageRef("t1", "tool", null),
  tests/HaloAgent.Tests/HistoryTurnSliceTests.cs: Assert.True(HistoryTurnSlice.TryResolve(Messages(), "t1", out var slice));
```

但这些 `s1` / `t1` 是测试 fixture 里的**会话 id、tool 消息 id**，根本不是 `need07` / `P007` 这类过程编号——纯属误报。

## 复现步骤

1. 在新增测试文件中写 `setActiveSessionId('s1')`、`new HistoryMessageRef("t1", "tool", null)` 之类的短 id。
2. `git add` 后执行 `node build/check-naming-hygiene.mjs --cached`。
3. 守卫把这些行判为违规，`exit 1` 拦住提交。

## 根因

守卫黑名单里有一条匹配「单字母 + 数字」的正则，且带 `i` 标志（大小写不敏感）：

```js
/\b[SHFTRBE][-_\s]?\d+(?:[-.]\d+)*\b/i
```

本意是抓 `S1` / `H4` / `T2` 这类阶段编号，但大小写不敏感后，`s1` / `t1` / `r1` 等小写测试 id 全部命中——**测试数据的字母 id 与阶段编号在字面上无法区分**。这正是规范里「测试数据内容需人工判断」那条边界的具体体现：纯正则扫描做不到人工判断，只能误伤。

## 解法（最小改动）

不放松门禁正则（放松会漏掉真正的过程编号），而是改测试数据 id，让它不含「字母+数字」形态：

- `s1` → `sess-a`（会话 id）
- `t1` → `tool-a`（tool 消息 id）
- 连带 `recoveryToken: 'replay:s1:u1'` → `'replay:sess-a:u1'`

改完重跑 `node build/check-naming-hygiene.mjs --cached`，守卫通过，正常提交。u1 / a1 / w1 等 id 的首字母不在 `[SHFTRBE]` 集合内，本来就不会被匹配，无需改。

## 关联提交 / PR

- 加固历史操作提交：包含 `useAgentTurn.replay.spec.ts`、`HistoryAnchorProjectorTests.cs`、`HistoryTurnSliceTests.cs` 的 id 调整。
- 门禁脚本：`build/check-naming-hygiene.mjs`；规范背景见 `docs/CEFSHARP_ARCHITECTURE_STANDARD.md` 第七节「命名卫生铁律」。

## 教训（下次如何避开）

1. **写测试 fixture id 时，前缀用字母词而非「单字母+数字」**：优先 `sess-a` / `tool-a` / `user-b` 这类「语义词 + 连字符」形态，从源头避开门禁正则。别偷懒用 `s1` / `t1` / `r1`。
2. **提交前先跑守卫**：`git add` 后手动跑一次 `node build/check-naming-hygiene.mjs --cached`，别等 pre-commit 拦下来才处理。
3. **误报时优先改数据、不动门禁**：正则针对的是真实编号红线，为一处测试数据放宽它会打开漏判口子；只有确认正则本身逻辑错误（如本例确需长期兼容小写测试 id）才考虑收紧/加白名单，且要配套反例回归。

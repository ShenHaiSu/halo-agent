# 无正文轮次显示成 8 个雷同折叠栏：展示粒度错了，不是渲染坏了

- 日期：2026-10-24
- 环境：Win10 x64 / Node 22 / Vue 3.5.43 / Pinia 2.3.1 / naive-ui 2.45.3
- 现象：
  模型在某次提问里只思考、只调工具、不返回正文时，一轮 ReAct 下来界面会冒出 **8 个长得几乎一样的
  `🧠 思考与工具调用 · N 个工具` 折叠栏**。用户从上往下滚，既不知道总共做了多少事，
  也不知道这些行其实属于「同一次提问」。
- 复现步骤：
  1. 提一个会触发多步工具编排的问题（例如"查一下仓库状态再跑测试"）。
  2. 让模型连续 8 次调工具、每次都不输出正文。
  3. 结束后看时间线：8 个独立折叠栏（而不是 1 个汇总舱）。
- 根因：
  **展示层分组粒度 = iteration，而用户的阅读单位 = 一次提问。**
  - 后端每个 ReAct 迭代必落一条 assistant，且 `content` 允许为 null（`HistoryAppender.cs` 的
    `UnifiedChatMessage.Assistant(...)`），所以 `messages.jsonl` 里天然是「8 条无正文 assistant」。
  - 前端 `buildTurnGroups` 遇到 assistant 就 flush 出新组（`turnGroup.ts`），
    于是分组粒度被锁死在 iteration，UI 上就变成 1:1 的 8 个折叠栏。
  - 链路里**每一段都是对的**，缺的只是「同一用户轮次」这一层聚合——所以正确做法是
    **在下游加一层纯函数，而不是改分组、改落盘、改事件契约**。
- 解法（最小改动）：
  1. 新增纯函数 `features/session/utils/turnRun.ts`：`isGhostTurn`（content 为空 / 孤立 tool 组）
     + `buildTurnRuns`（把**连续、无正文**的 turn 组折叠成一个 `TurnRun`，遇有正文 turn / user / system 即断开）。
  2. 只在一个地方接入：`useTimeline.timelineItems = computed(() => turnRunKillSwitch ? raw : buildTurnRuns(raw, …))`，
     `historyEntries` / `tailEntries` 的切分逻辑一行不动。
  3. 新增 `TurnRunItem.vue`（汇总行 + `n-collapse-transition`）+ `RunStepList.vue`（按 iteration 分节，便于复用）。
  4. 加 kill switch `localStorage['halo-turn-run'] = 'off'`，可整体回退到改动前行为。
- 关联提交 / PR：
  `feat(web): need-01-P1 新增无正文轮次合并纯函数`、`feat(web): need-01-P2 时间线合并无正文轮次为单个折叠舱`、
  `feat(web): need-01-P3 活动轨并入合并舱消除舱体忽隐忽现`
- 教训（下次如何避开）：
  - **先分清「渲染错了」还是「分组粒度错了」。** 同一个视觉症状（一堆雷同的行），
    根因可能在数据成型的那一步；在后端/落盘/事件契约上找问题会白费一整天。
  - **聚合层只读不写。** 增量归并（`buildTurnGroupsIncremental`）靠**引用复用**做 memo，
    聚合层一旦就地 `push`/改字段，memo 命中就会返回脏数据。只新建对象、只读 `TurnGroup`。
  - **聚合键必须由「首个成员」派生且稳定**（`run.key = 'run-' + groups[0].key`）。
    用「成员数量」或「末成员」派生 key，会让 `v-for` 每帧重建 DOM、滚动位置丢失。
  - **不要吞掉目录的粒度。** 目录（Toc）只认 `user/system/turn` 三种 kind，把聚合后的
    `turn-run` 喂给它，条目会静默落进 system 被过滤掉——目录看起来像"历史丢了"。
  - **单步不合并**（1 步也套壳只是多一次点击）。只有"正在运行的那一步"是例外，
    否则运行中会出现「1 个舱 ↔ 独立一步」的忽隐忽现。
  - **运行时开关优于回滚发布**：这类纯展示改动一定配 kill switch，
    让"逐像素一致"成为可实测的事实，而不是口头保证。
